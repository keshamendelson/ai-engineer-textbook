Матрицы

В этой главе вы разберёте, что такое матрица и как она применяет сразу набор линейных операций к вектору. Это знание нужно для понимания устройства линейных слоёв нейросети, из которых состоит любая современная модель.

Задача этой главы

Что нужно помнить из главы 1.1

Вектор это упорядоченный список чисел, каждый элемент которого соответствует отдельной характеристике объекта. В предыдущей главе вы уже использовали векторы для описания оценок пиццы, подсчёта их длины и вычисления косинусной близости между вариантами.

Скалярное произведение двух векторов одинаковой длины считают как сумму произведений элементов на одинаковых позициях. В результате всегда получается одно обычное число, это скаляр.

Вся текущая глава опирается только на скалярное произведение. Дополнительных математических понятий вам не понадобится.

В этом разделе мы решим задачу на оценку пиццы. Вектор вкуса пиццы A равен [8, 2]: первый элемент соответствует количеству сыра, второй, уровню остроты. В зал зашли три посетителя: Вася любит сыр и не переносит острое, Петя посещает заведение только за острой пиццей, Маша рада любому варианту. Нам нужно по одному вектору пиццы получить сразу три оценки: от Васи, Пети и Маши.

Вкус каждого посетителя описывается вектором той же размерности, что и вектор пиццы. Число на позиции признака показывает, сколько очков этот признак приносит итоговой оценке, отрицательное значение означает, что признак снижает общую оценку. Векторы вкусов для этой задачи фиксированы: Вася [1, -1], Петя [0, 2], Маша [1, 1]. Другие векторы вкуса в этом разделе не используются.

Оценка каждого посетителя считается как скалярное произведение вектора его вкуса на вектор пиццы. Для Васи это 1·8 + (-1)·2 = 6, для Пети 0·8 + 2·2 = 4, для Маши 1·8 + 1·2 = 10. Получаем вектор оценок [6, 4, 10]. Если записать три вектора вкуса как строки одной таблицы, умножение таблицы на вектор пиццы даёт сразу все три оценки. Это и есть основная идея матрицы: вместо отдельных вычислений для каждого посетителя мы обрабатываем пачку запросов одним действием. В линейных слоях нейросети матрица задаёт вектору сразу пачку вопросов, и из этого одного действия собран каждый такой слой.

Считаем руками · три оценки одной пиццы

Возьмём три вектора вкуса: Вася [1, -1], Петя [0, 2], Маша [1, 1]. Пицца A описывается вектором [8, 2]. Чтобы получить оценку каждого посетителя, считаем скалярное произведение вектора вкуса на вектор пиццы: перемножаем соответствующие координаты и складываем результаты.

Для Васи: 1 умножить на 8 даёт 8, минус 1 умножить на 2 даёт минус 2, сумма равна 6. Для Пети: 0 умножить на 8 даёт 0, 2 умножить на 2 даёт 4, итого 4. Для Маши: 1 умножить на 8 даёт 8, 1 умножить на 2 даёт 2, сумма равна 10.

Итоговый вектор оценок равен [6, 4, 10]. Исходный вектор из двух чисел, описывающий пиццу, превратился в вектор из трёх чисел, где каждая координата соответствует оценке одного посетителя. Каждое скалярное произведение даёт ровно одну координату результата. Так как в примере только три вектора вкуса, ответ всегда одинаковый: [6, 4, 10].

В разделе 1.1 вы три раза выполняли одно и то же действие: считали скалярное произведение вектора вкусов пиццы и вектора предпочтений одного посетителя, чтобы получить его итоговую оценку. Каждый раз вы меняли только второй вектор: сначала брали предпочтения Васи, потом Пети, потом Маши, а вектор вкусов пиццы оставался неизменным. Все три вектора предпочтений можно объединить в одну таблицу и применять её к вектору вкусов целиком, вместо трёх отдельных вычислений. Такую таблицу называют матрицей. В этой главе мы будем работать с матрицей, строки которой соответствуют векторам вкусов этих трёх посетителей. При умножении этой матрицы на вектор вкусов пиццы [8, 2] вы сразу получите все три оценки за один шаг: [6, 4, 10].

Шаг 1. Что такое матрица

Матрица это прямоугольная таблица чисел, записанная в фиксированном порядке. Размер матрицы обозначают двумя натуральными числами: сначала количество строк, потом количество столбцов. Порядок этих чисел не меняется без отдельного указания. Например, таблица вкусов трёх пользователей по двум видам пиццы имеет размер три на два: три строки, по две ячейки в каждой.

Сама по себе матрица не несёт смысла, это просто набор чисел в ячейках. Смысл появляется только по договорённости о том, как читать её строки и столбцы. В нашем примере каждая строка соответствует одному пользователю и хранит его оценки по двум признакам: сыр и пепперони. Если поменять местами строки, изменится соответствие оценок конкретным пользователям. Каждый столбец соответствует одному признаку и хранит оценки всех пользователей по нему.

Векторы вкусов пользователей в этой главе фиксированы, других вариантов в примерах нет. Результат скалярного произведения матрицы на вектор признаков всегда равен [6, 4, 10]. Такая фиксация исключает неоднозначность при вычислениях.

Шаг 2. Правило умножения целиком

Чтобы умножить матрицу на вектор, возьмите первую строку матрицы, посчитайте её скалярное произведение с вектором и запишите результат первым элементом итогового вектора. Затем выполните то же действие для второй строки, потом для третьей и так до последней.

В этой операции дополнительные действия не требуются. Каждый элемент итогового вектора получается строго по указанному правилу: нет промежуточных шагов, сложения строк между собой или дополнительных преобразований. Длина итогового вектора всегда равна количеству строк исходной матрицы, а длина вектора, на который умножают матрицу, должна совпадать с количеством столбцов в этой матрице. Это простое построчное правило используется в каждом линейном слое нейросети: когда на вход слоя подаётся вектор признаков, матрица весов слоя сразу применяет его и преобразует входной вектор в выходной за один шаг.

Считаем руками · матрица покрупнее

Умножение матрицы на вектор работает по строкам: каждая строка матрицы даёт ровно один элемент результирующего вектора. Вы уже знаете, что для этой операции количество столбцов в матрице должно совпадать с длиной вектора. Возьмём матрицу W размером 3 на 4 и вектор x длины 4. Строки матрицы W: [0.2, -1.1, 0.7, 0.0], [1.4, 0.3, -0.2, 0.9], [-0.5, 0.8, 1.2, -0.4]. Вектор x равен [1.0, 2.0, 0.5, 3.0].

Разберём расчёт для первой строки по шагам, чтобы не допустить ошибок. 0.2 умножить на 1.0 даёт 0.2. 1.1 умножить на 2.0 даёт 2.2, со знаком минус получаем -2.2. 0.7 умножить на 0.5 даёт 0.35. 0 умножить на 3.0 даёт 0. Суммируем все полученные значения: 0.2 - 2.2 + 0.35 + 0 = -1.65.

Расчёт для второй строки выполняется по тому же правилу: перемножаем соответствующие элементы строки и вектора, затем складываем результаты. 1.4·1.0 + 0.3·2.0 + (-0.2)·0.5 + 0.9·3.0 = 1.4 + 0.6 - 0.1 + 2.7 = 4.6. Третья строка считается по тому же принципу: перемножаем пары элементов и суммируем результаты. (-0.5)·1.0 + 0.8·2.0 + 1.2·0.5 + (-0.4)·3.0 = -0.5 + 1.6 + 0.6 - 1.2 = 0.5.

Итоговый результат имеет длину 3, как и количество строк в исходной матрице: [-1.65, 4.6, 0.5]. Таким образом, матрица 3 на 4 превратила вектор длины 4 в вектор длины 3.

Попробуйте · матрица вкусов

Двигайте состав пиццы и наблюдайте, как меняются три оценки. Матрица вкусов при этом остаётся неизменной: в нейросетях такие неизменяемые параметры называют весами. Когда количество острого превышает количество сыра, оценка Васи становится отрицательной.

Шаг 3. Правило размерностей и откуда оно берётся

Умножить матрицу на вектор можно только если количество столбцов матрицы совпадает с длиной вектора. Возьмём матрицу размера 3 на 2: у неё три строки, в каждой по два числа. При умножении на вектор длины 2 каждая строка матрицы вычисляет скалярное произведение с этим вектором, в результате получается вектор из трёх чисел. Если взять вектор длины 5, для трёх строк матрицы не хватит пар элементов для расчёта, операция не будет определена.

Это правило можно записать кратко: матрица размера m×n, умноженная на вектор длины n, даёт вектор длины m. Внутреннее число n в этом случае должно совпасть, после умножения оно больше не фигурирует в описании результата. Внешние числа m задают форму итогового вектора.

При написании кода с линейными слоями полезно проговаривать это правило вслух для каждого умножения матрицы на вектор. Это помогает вам избежать ошибок в размерностях, которые часто возникают при изменении архитектуры сети, и сэкономить время, которое обычно уходит на отладку несовместимых тензоров.

Грабли · больше половины ошибок новичка это форма

Сообщение mat1 and mat2 shapes cannot be multiplied (32x768 and 512x768) означает ровно одно: внутренние размерности матриц не совпали. У первой матрицы 768 столбцов, у второй 512 строк, общих индексов для попарного умножения элементов нет. Никаких скрытых причин, кроме несовпадения формы, в этой ошибке нет.

Лечение простое: печатайте .shape после каждой операции с тензорами, пока формы не станут очевидными даже без запуска кода. В PyTorch, NumPy и TensorFlow этот атрибут возвращает кортеж размерностей за доли секунды, и это быстрее, чем отлаживать падение метрик на последнем слое сети.

Числа в формуле читаются слева направо в том же порядке, в котором записано умножение. Ошибка в таких случаях обычно появляется из-за перепутанного порядка сомножителей или забытого транспонирования матрицы. Проверяйте, не стоит ли матрица, которую нужно транспонировать, на месте сомножителя, у которого размерность должна совпасть с количеством строк первой.

Грабли · деление на сумму по строкам

При работе с матрицами в библиотеках для вычислений на Python, например NumPy или PyTorch, вы можете столкнуться с ошибкой, связанной с делением на сумму по строкам.

Допустим, у вас есть матрица A размера 3 на 4. При вызове A.sum(axis=1) по умолчанию возвращается вектор длины 3. Попытка выполнить деление A / A.sum(axis=1) либо падает с ошибкой несовпадения размерностей, либо даёт неверный результат: библиотека пытается сопоставить вектор из 3 элементов с 4 столбцами исходной матрицы.

Чтобы избежать этой проблемы, при вычислении суммы передавайте параметр keepdims=True: A.sum(axis=1, keepdims=True) вернёт таблицу размера 3 на 1, и деление будет выполнено по строкам корректно, как вы задумали.

Шаг 4. Почему в коде всё на одну ось больше

В примерах этой главы мы умножали матрицу вкусов на один вектор предпочтений пользователя. В реальных программах вы почти не будете использовать такой подход: видеокарта простаивает, если на один расчёт выделить только один пример. Вместо этого собирают пачку примеров и обрабатывают её за один вызов. Эту пачку называют батчем. Тогда на вход вместо вектора длины 2 подаётся таблица размера 64 на 2, а на выходе получается таблица 64 на 3. По каждой строке выходной таблицы лежат оценки для соответствующего примера из батча. Правило остаётся тем же: одну и ту же матрицу вкусов применяют ко всем строкам входной таблицы сразу.

Наборы чисел с любым количеством осей называют тензорами. Одна ось даёт вектор, две оси дают матрицу, а при трёх и более осях такие наборы тоже называют тензорами. Библиотеки вроде NumPy и PyTorch работают со всеми этими случаями по единому принципу, вам не придётся отдельно прописывать логику для векторов и матриц. В этой главе мы используем ровно три вектора вкусов: Вася [1, -1], Петя [0, 2], Маша [1, 1]. Другие векторы вкуса здесь не рассматриваются, поэтому умножение матрицы на любой из этих трёх всегда даёт результат [6, 4, 10].

Промежуточный итог

Это таблица чисел, матрица, где каждая строка задаёт входному вектору отдельный вопрос через скалярное произведение. Количество строк в ней равно количеству чисел на выходе слоя, количество столбцов совпадает с размерностью входного вектора. Это определение напрямую связывает линейную алгебру с работой нейросети.

Если в слой передаёте не один вектор, а пачку векторов, то есть батч, матрица превращается в тензор с дополнительной осью, где хранится номер примера. Все операции с матрицей сразу работают с этим тензором, поэтому код для обработки одного вектора и для батча почти не отличается.

Шаг 5. Где это встречается в нейросети

Линейный слой нейросети выполняет три последовательных шага. На вход подаётся вектор признаков, его умножают на матрицу весов, к результату прибавляется вектор смещений, после чего применяют простую нелинейная функция. Именно первое из этих трёх действий, умножение вектора на матрицу, мы разбирали на протяжении всего урока. Про два остальных шага речь пойдёт в главе 3.

Числа внутри матрицы весов называют весами. В нашем примере с оценками вкусов мы подобрали их вручную: вектор Васи [1, -1], вектор Пети [0, 2], вектор Маши [1, 1]. Для этих значений итоговый ответ всегда равен [6, 4, 10]. В реальной нейросети веса подбирает алгоритм обучения: он сравнивает ответы модели с правильными значениями, вычисляет ошибку и корректирует веса, чтобы эта ошибка уменьшалась. Подробнее о работе этого процесса рассказывается в главе 1.3, а его реализация для глубоких сетей разбирается в главе 4. Другие векторы вкуса в этой главе мы не используем.

Аналогия

Представьте матрицу как станок на производственном конвейере. На вход подаётся заготовка заданной формы, это вектор нужной размерности, а на выходе получается деталь совершенно другой формы. Все числовые настройки этого станка, которые определяют, как именно из входной заготовки получится выходная деталь, хранятся прямо внутри матрицы. При обучении нейросети мы подкручиваем настройки каждого такого станка на конвейере, чтобы в итоге получить нужный результат.

Эта аналогия не является полной. Настоящий станок настраивает человек, который смотрит на получившуюся деталь и понимает, правильная она или нет. В случае с нейросетью настройки матрицы корректирует алгоритм. Для подстройки он использует одно число ошибки между предсказанным и нужным результатом, а не саму выходную деталь. Он повторяет эту операцию миллионы раз для тысяч разных заготовок.

Считаем руками · сколько чисел в одном слое

Линейный слой умножает входной вектор на матрицу весов. Если слой принимает на вход вектор длины 4096 и возвращает вектор такой же длины, его матрица весов имеет 4096 строк и 4096 столбцов. Произведение количества строк и столбцов равно 4096 * 4096 = 16 777 216. Это почти семнадцать миллионов отдельных чисел в одной таблице.

В современных нейросетях таких линейных слоев используют десятками, а внутри каждого может быть несколько матриц весов. Из-за этого суммарное количество параметров модели быстро достигает миллиардов.

Если каждое значение веса хранится в формате, занимающем 2 байта, то семь миллиардов параметров занимают около четырнадцати гигабайт оперативной памяти или места на диске.

Шаг 6. Умножение матрицы на матрицу и цена скобок

Библиотеки для численных вычислений, например NumPy, умножают матрицу на матрицу по стандартному правилу, которое продолжает логику операции умножения матрицы на вектор, разобранной ранее. Элемент в ячейке на пересечении i-й строки первой матрицы и j-го столбца второй равен скалярному произведению этих двух векторов. Проще представить вторую матрицу как набор векторов-столбцов, поставленных бок о бок: тогда умножение матриц сводится к повторению операции умножения матрицы на вектор для каждого из этих столбцов по отдельности.

Правило совместимости размерностей остаётся прежним: если первая матрица имеет размер m×n, а вторая n×k, результат будет матрицей размера m×k. Количество столбцов первой матрицы должно совпадать с количеством строк второй, иначе операция не определена.

Порядок сомножителей менять нельзя. В общем случае произведение A×B и произведение B×A дают разные матрицы, а часто второе даже не может быть вычислено из-за несовпадения размерностей. Например, умножение матрицы 2×3 на матрицу 3×4 даёт матрицу 2×4, а обратное умножение 3×4 на 2×3 не определено вообще. Это отличие от умножения скаляров, где порядок не влияет на результат.

Считаем руками · во сколько обходятся скобки

Умножение матриц ассоциативно, но порядок расстановки скобок влияет на количество операций и объём промежуточной памяти. Стоимость умножения матрицы размера m на n на матрицу n на k равна m·n·k операций. Возьмём три матрицы: A размера 1 на 1000, B размера 1000 на 1000 и C размера 1000 на 1. При вычислении (AB)C сначала умножаем A и B: это 1·1000·1000 = 1 000 000 операций, потом результат (матрица 1 на 1000) умножаем на C: 1·1000·1 = 1000 операций. Итого около миллиона операций.

При вычислении A(BC) сначала умножаем B и C: 1000·1000·1 = 1 000 000 операций, потом A умножаем на полученную матрицу 1000 на 1: 1·1000·1 = 1000 операций. В этом примере оба способа дают похожую стоимость, но результат умножения полностью совпадает.

Если изменить размер C на 1000 на 1000, картина изменится. При (AB)C стоимость составит 1 000 000 + 1 000 000 000 операций, а при A(BC), 1 000 000 000 + 1 000 000. На больших матрицах разница достигает нескольких порядков, поэтому при реализации линейных слоёв нейросетей выбор порядка вычислений влияет на скорость и потребление ресурсов.

Из ассоциативности умножения матриц получается полезное свойство. Если размерности матриц совпадают так, что последовательное умножение возможно, порядок расстановки скобок не меняет итоговый результат произведения: (AB)C = A(BC). Это свойство позволяет перегруппировывать вычисления без потери корректности и лежит в основе оптимизации производительности при обучении моделей.

Применим это утверждение к последовательности линейных слоёв. Если два линейных слоя идут друг за другом, а между ними нет нелинейной функции активации, их композиция даёт ровно тот же результат, что и один линейный слой с матрицей, равной произведению матриц исходных слоёв. Доказательство этого утверждения приведено в главе 3, а пока достаточно понимать, что ассоциативность позволяет объединять последовательные линейные преобразования в одно.

Отсюда получается вывод о роли нелинейности в глубоких моделях. Если в сети отсутствуют нелинейные функции между линейными слоями, добавление новых таких слоёв не расширяет множество функций, которые может реализовать модель. Глубина без нелинейности не даёт никаких новых возможностей по сравнению с одним линейным слоем.

Для любых трёх матриц A, B и C совместимых размерностей умножение матриц ассоциативно: верно равенство (AB)C = A(BC). При этом количество скалярных операций в каждом из вариантов может сильно отличаться, поэтому порядок вычислений влияет на скорость работы и расход памяти.

Эту особенность учитывайте на практике в слоях внимания, описанных в главе 8: там подряд умножаются три большие матрицы, и порядок действий часто подбирают вручную, чтобы уложиться в ограничения по объёму оперативной памяти.

В большинстве библиотек для машинного обучения, например PyTorch, оператор матричного умножения вычисляет результат слева направо. Поэтому расстановка скобок в коде влияет на производительность, и её нужно выбирать с учётом размеров входных матриц и доступных ресурсов.

Разбор и практика

Транспонирование и симметричные матрицы

Вы уже знакомы с базовыми операциями над векторами, теперь перейдём к операциям над матрицами. Транспонирование меняет строки и столбцы местами: элемент, стоявший на пересечении строки i и столбца j, переезжает на пересечение строки j и столбца i. Обозначается эта операция верхним индексом T, для матрицы A запись выглядит как AT.

Матрица размера m на n после транспонирования имеет размер n на m. Именно поэтому в коде при работе с батчем появляется запись WT: батч данных имеет форму (примеры, признаки), а для умножения на матрицу весов нужно подогнать её размерность. В библиотеках для работы с массивами, например NumPy, операция вызывается методом .T.

Транспонирование дважды возвращает исходную матрицу: (AT)T = A, потому что каждый элемент после двух перестановок возвращается на свою исходную позицию.

Операция транспонирования согласована со сложением: для любых двух матриц A и B одинакового размера (A + B)T = AT + BT. Это следует из того, что при сложении складываются элементы на одинаковых позициях, а транспонирование перемещает элементы всех матриц одинаковым образом.

Матрицу называют симметричной, если она совпадает со своей транспонированной, то есть A = AT. Наглядно это означает зеркальность относительно главной диагонали: элементы, стоящие симметрично относительно неё, равны между собой.

Возьмём квадратную матрицу A и рассмотрим сумму S = A + AT. Транспонируем её: ST = (A + AT)T.

По свойству согласованности транспонирования со сложением правая часть равенства преобразуется к виду AT + (AT)T. Так как двойное транспонирование возвращает исходную матрицу, (AT)T = A, поэтому выражение упрощается до AT + A.

Сложение матриц коммутативно, поэтому AT + A = A + AT, что по определению равно S. Получили ST = S, значит сумма любой квадратной матрицы с её транспонированной симметрична.

for label, fn in (("(PQ)R", lambda: (P @ Q) @ R), ("P(QR)", lambda: P @ (Q @ R))):

Коротко

  1. Под матрицей понимают прямоугольную таблицу чисел, её размер записывают как количество строк на количество столбцов.
  2. При умножении матрицы на вектор вычисляют скалярное произведение каждой строки матрицы с этим вектором. В результате получается столько же чисел, сколько строк в матрице.
  3. При умножении матрицы размера m на n на вектор длины n получается вектор длины m. Внутренние размерности матрицы и вектора должны совпасть.
  4. В коде добавляют ось батча, чтобы одну матрицу весов применить сразу к пачке примеров. Наборы чисел с любым числом осей называют тензорами.
  5. Каждый линейный слой нейросети начинается с умножения матрицы на вектор. Числа в этой матрице называют весами, а общее число параметров модели получают как сумму чисел во всех её матрицах.
  6. Умножение матриц ассоциативно, поэтому результат не зависит от расстановки скобок, но время вычислений и потребление памяти при этом могут сильно отличаться.

Проверьте себя

Всего 7 вопросов. Ответы показываются сразу с объяснением.

1. Матрица размера 768 на 512 умножается на вектор. Какой длины должен быть этот вектор и какой длины будет результат?

Размер матрицы записывается как строки на столбцы, значит у неё 768 строк и 512 столбцов. При умножении на вектор длина вектора должна совпадать с количеством столбцов, то есть 512. Результат имеет длину, равную числу строк, то есть 768. Вариант с входом 768 неверен: длина вектора не совпадает с количеством столбцов, умножение невозможно. Вариант с одинаковой длиной 768 неверен. Вариант с любой длиной неверен, размерности должны совпадать.

2. Матрица [[2, 0], [1, 3]] умножается на вектор [5, 1]. Что получится?

Правильный ответ, [10, 8]. При умножении матрицы на вектор строка матрицы умножается на вектор: первая строка [2, 0] даёт 2*5 + 0*1 = 10, вторая [1, 3], 1*5 + 3*1 = 8. Вариант [10, 3] получается при пропуске второго слагаемого во второй строке, [7, 4], при ошибочном сложении по столбцам, а [10, 0, 5, 3], результат перемножения элементов по отдельности, а не умножения матрицы на вектор.

3. Код падает с ошибкой несовпадения форм при умножении. Что вы проверяете в первую очередь?

Ошибка о несовпадении форм возникает только при несоответствии размерностей сомножителей, поэтому первым делом проверяют совпадение внутренних чисел размерностей и правильный порядок множителей. Чаще всего проблема в перепутанном порядке сомножителей или забытом транспонировании. Нехватка памяти на видеокарте вызывает отдельную ошибку, инициализация весов не влияет на форму тензоров при умножении, размер батча не связан с этой проблемой.

4. Что имеют в виду, когда говорят «модель на семь миллиардов параметров»?

Правильный ответ верен, потому что параметры модели это веса, то есть числа, хранящиеся в матрицах всех линейных слоёв, а их суммарное число и составляет семь миллиардов. При двух байтах на число такой набор параметров занимает около четырнадцати гигабайт. Вариант с семью миллиардами примеров описывает размер обучающей выборки, вариант с токенами объём входных данных, а вариант с семью миллиардами слоёв не имеет отношения к числу параметров.

5. Почему в коде появляется дополнительная ось батча?

Верный вариант описывает пакетную обработку. Вы применяете одну матрицу весов ко всем строкам батча за один проход. Это не делает модель точнее и не хранит веса компактнее. Правило размерностей тут ни при чём. Зато одна крупная операция вместо многих мелких лучше загружает видеокарту и ускоряет расчёты.

6. Вам нужно перемножить три матрицы: A размером 1 на 1000, B размером 1000 на 1000 и C размером 1000 на 1000. Как расстановка скобок влияет на итоговый результат?

Умножение матриц ассоциативно, поэтому результат при любой расстановке скобок одинаковый, вариант с разным результатом сразу неверный. При (AB)C сначала перемножают узкую матрицу A и B, получают строку 1 на 1000, после чего её умножают на C, это очень мало операций. При A(BC) сначала перемножают две большие матрицы B и C, что занимает около миллиарда операций, поэтому такой порядок заметно медленнее. Варианты с совпадением времени или преимуществом A(BC) неверные.

7. Для матрицы A размером 3 на 4 вы посчитали сумму по оси 1 через A.sum(axis=1), а потом разделили исходную матрицу на полученный вектор сумм. Что получится в результате?

Правильный ответ верен: суммирование по оси 1 схлопывает её, получается вектор длины 3, а у матрицы 4 столбца, поэтому библиотека не может сопоставить размерности при делении, возникает ошибка. Первый вариант неверен: деление не проходит из-за несовпадения форм. Второй неверен: axis=1 суммирует по строкам, а не столбцам. Третий неверен: ошибка связана с несовпадением форм, а не с типом оборудования. Чтобы делить по строкам, используют keepdims=True, сохраняющий ось в виде размерности 1.
