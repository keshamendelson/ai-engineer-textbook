Когда табличные данные выгоднее отдать дереву

Табличные данные состоят из строк, где каждая строка описывает один объект, и столбцов, где каждый столбец хранит признак: числовое значение, категорию, дату. Между столбцами нет заранее заданного порядка или отношения соседства. Обучение с учителем из главы 2 работает с такими признаками, но модели для работы с изображениями и звуком из глав 28 и последующих построены вокруг связи между соседними элементами. Свёртка и механизм внимания эксплуатируют эту связь: они анализируют, как значение одного пикселя зависит от значений рядом стоящих, как один отсчёт звука связан с соседними отсчётами.

В таблице такой связи между признаками нет. Возьмём строку с возрастом клиента, городом проживания, доходом и датой последней покупки. Поменяйте местами столбцы с доходом и датой покупки, и задача классификации или регрессии не изменится. Для сравнения вспомните свёрточную сеть из главы 28, которой на вход подавали картинку с перемешанными пикселями. Она не смогла бы найти осмысленные паттерны и показала бы случайный результат.

Без пространственной или последовательной структуры нейросеть теряет своё главное преимущество. Ей приходится заново учить нужные комбинации признаков для каждого нового набора табличных данных, что часто занимает больше времени и даёт худшее качество, чем специализированные модели на основе деревьев решений.

Решающее дерево работает с сырыми категориальными признаками и пропусками без предварительной обработки, что особенно ценно на этапе быстрой прототипизации. Оно не требует нормализации столбцов: доход в рублях и возраст в годах можно подать как есть, а пороги наращиваются алгоритмом во время обучения. На выборках в тысячи или десятки тысяч строк дерево достигает приличного качества, не требуя миллионов весов, которые нужны нейросети.

На очень больших табличных наборах, миллионы строк, разрыв в качестве с нейросетью сокращается. Особенно там, где внутри строк есть текстовые описания или временные ряды, нейросеть начинает эксплуатировать скрытую структуру, которую дерево не видит. В таких случаях выбор модели становится менее однозначным.

Дальше в главе разбираются три модели этого семейства по нарастанию сложности. Сначала решающее дерево, затем случайный лес, в котором несколько деревевьев голосуют, и градиентный бустинг, который последовательно исправляет ошибки предыдущих деревьев. В конце глава возвращается к практическому выбору между бустингом и сетью на конкретных признаках задачи.

Решающее дерево

Решающее дерево (decision tree) это модель обучения с учителем. Его структура строится по иерархическому принципу: в корневой узел попадают все объекты обучающей выборки. Каждый внутренний узел проверяет ровно один признак по заданному порогу, например условие «доход выше 80000». Объекты, для которых условие выполняется, отправляются в правого потомка, остальные, в левого. Процедура повторяется рекурсивно для каждого нового узла, пока не останутся узлы, в которых дальнейшее разбиение не даёт заметного улучшения качества. Эти конечные узлы называются листьями.

Предсказание зависит от типа задачи. Для классификации в листе запоминается класс большинства объектов, попавших в него при обучении. Для регрессии, среднее значение целевой переменной среди этих объектов. При использовании готового дерева объект проходит по цепочке проверок от корня до одного из листьев, и возвращается соответствующее значение.

Построение дерева реализуется как жадный процесс. На каждом шаге алгоритм перебирает все доступные признаки и возможные пороги для них, выбирает разбиение, которое даёт наибольшее улучшение по выбранному критерию, например по приросту информации на основе энтропии. После выбора разбиения процедура рекурсивно повторяется для каждого из двух новых узлов отдельно. Ключевая особенность этого подхода в том, что алгоритм никогда не откатывается и не пересматривает разбиение, сделанное на предыдущем шаге, даже если позже выяснится, что другой выбор в самом начале дал бы лучшее дерево в целом.

При построении решающего дерева на каждом шаге нужно выбрать признак и порог разбиения, которые лучше всего разделят объекты по классам. Для оценки качества разбиения используют критерии, основанные на мере неопределённости множества объектов. Один из таких критериев строится на энтропии: для множества с долями классов p₁, ..., pₖ она вычисляется по формуле H = -Σ pᵢ log₂(pᵢ). Энтропия равна нулю, если все объекты узла принадлежат одному классу, то есть узел чистый. По мере перемешивания классов в узле энтропия растёт и достигает максимума при равных долях всех классов.

На практике часто используют альтернативный критерий, индекс Джини (Gini impurity). Он измеряет вероятность ошибки, если случайно присвоить объекту узла метку по распределению классов этого узла. Индекс Джини не требует вычисления логарифма, поэтому работает быстрее на больших выборках. В библиотеке scikit-learn по умолчанию для DecisionTreeClassifier используется индекс Джини, а энтропию можно включить параметром criterion="entropy". Разница в итоговом качестве модели между двумя критериями на большинстве задач небольшая.

Когда дерево выбирает разбиение, оно максимизирует прирост информации (information gain). Эта величина показывает, насколько уменьшится энтропия узла после разбиения на двух потомков, взвешенная по размеру каждого потомка. Чем больше прирост информации, тем лучше разбиение разделяет классы. Полный числовой пример расчёта энтропии и прироста информации приведён в блоке ниже.

Вывод: прирост информации на числовом примере из 10 объектов

Возьмём узел решающего дерева с 10 заявками на кредит: 6 из них одобрены, это класс A, 4 отклонены, это класс B. Энтропия множества с долями классов p_A и p_B считается по формуле H = -p_A * log2(p_A) - p_B * log2(p_B).

Для родительского узла p_A = 6/10 = 0.6, p_B = 4/10 = 0.4. Округлённые значения логарифмов: log2(0.6) ≈ -0.737, log2(0.4) ≈ -1.322. Подставляем в формулу: H(узел) = -0.6*(-0.737) - 0.4*(-1.322) = 0.442 + 0.529 = 0.971 бита.

Рассмотрим кандидата на разбиение: признак «доход выше порога», ответ да или нет. Левый потомок (ответ да) получает 4 заявки, все 4 одобрены, 0 отклонённых. Правый потомок (ответ нет) получает 6 заявок, 2 одобренных, 4 отклонённых. Проверка по суммам: 4 + 2 = 6 одобренных и 0 + 4 = 4 отклонённых, что совпадает с распределением в родительском узле.

Энтропия левого потомка: p_A = 4/4 = 1, p_B = 0/4 = 0. Оба слагаемых формулы равны нулю по определению: 1 * log2(1) = 0, а 0 * log2(0) по соглашению тоже считается нулём. Итог: H(левый) = 0 бит, узел чистый, разбивать его дальше нет смысла.

Энтропия правого потомка: p_A = 2/6 ≈ 0.333, p_B = 4/6 ≈ 0.667. Округлённые значения логарифмов: log2(0.333) ≈ -1.585, log2(0.667) ≈ -0.585. Подставляем в формулу: H(правый) = -0.333*(-1.585) - 0.667*(-0.585) = 0.528 + 0.390 = 0.918 бита.

Взвешиваем энтропию потомков по доле объектов, попавших в каждый из них: взвешенная энтропия после разбиения равна (4/10)*H(левый) + (6/10)*H(правый) = 0.4*0 + 0.6*0.918 = 0 + 0.551 = 0.551 бита.

Прирост информации считается как энтропия узла до разбиения минус взвешенная энтропия после разбиения: 0.971 - 0.551 = 0.420 бита. Алгоритм повторяет этот расчёт для каждого другого кандидата на разбиение: другой порог дохода, возраст, число открытых продуктов, и выбирает то разбиение, у которого прирост информации оказался наибольшим.

Если дереву разрешить расти до состояния, когда в каждом листе остаётся ровно один объект из обучающей выборки, оно способно безошибочно предсказать целевой признак для всех примеров, на которых обучалось. При этом оно запоминает не только общие закономерности, но и случайный шум, единичные выбросы, не характерные для общей зависимости. На новых данных такое дерево почти всегда показывает качество заметно хуже, чем на обучающей выборке. Это тот же эффект переобучения, который разбирался в главе 5.

Существует два основных подхода к ограничению роста дерева. Первый, обрезка до роста, останавливает разбиение узлов ещё на этапе построения. Для этого задают максимальную глубину дерева параметром max_depth, минимальное число объектов в узле, необходимое для дальнейшего разбиения min_samples_split, или минимальное число объектов в конечном листе min_samples_leaf. Дерево не дорастает до состояния с одним объектом на лист и не успевает подогнаться под шум обучающей выборки.

Второй подход, обрезка после роста, предполагает сначала выращивание дерева до максимально возможной глубины, а затем последовательное удаление тех поддеревьев, отказ от которых почти не ухудшает качество предсказаний на отдельной отложенной выборке. Эта техника называется обрезкой по минимальной цене сложности, в библиотеке scikit-learn она доступна через параметр ccp_alpha у класса DecisionTreeClassifier.

На практике в большинстве задач достаточно ограничить глубину дерева и минимальный размер листа, подобрав оба значения с помощью кросс-валидации, описанной в главе 5. Этот способ реже приводит к сильному недообучению, чем полная обрезка после роста, и требует меньше вычислений при подборе гиперпараметров.

Аналогия

Постройку решающего дерева удобно сравнивать с игрой в двадцать вопросов, где один игрок загадывает объект, а второй пытается его угадать, задавая только вопросы с ответом «да» или «нет». Каждый вопрос сокращает круг возможных вариантов: хороший вопрос делит оставшихся кандидатов примерно пополам и сильно снижает неопределённость, плохой почти не сужает круг возможных ответов.

На каждом шаге построения дерево ищет ровно такой вопрос про один признак и один порог, который сильнее всего снижает энтропию текущего набора объектов, то есть задаёт самый информативный из всех доступных на этом шаге вопросов.

Как и в игре, порядок вопросов имеет значение. Жадный выбор лучшего вопроса прямо сейчас не гарантирует кратчайший или самый удачный путь к ответу в целом: дерево просто не умеет заглядывать на два шага вперёд.

Что такое индекс Джини простым языком

Индекс Джини измеряет примесь в узле дерева. Узел это группа объектов, попавших в одну вершину при построении модели. Примесь показывает, как часто модель ошибаётся, если предсказывает самый частый класс в этой группе. Формула индекса Джини: один минус сумма квадратов долей классов. Доля класса это число объектов этого класса делённое на общее число объектов в узле.

Разберём на примере десяти кредитных заявок. В узле семь одобрений и три отказа. Доля одобрений равна 0,7. Доля отказов равна 0,3. Квадрат доли одобрений: 0,7 умножить на 0,7 равно 0,49. Квадрат доли отказов: 0,3 умножить на 0,3 равно 0,09. Сумма квадратов: 0,49 плюс 0,09 равно 0,58. Индекс Джини: один минус 0,58 равно 0,42. В расчёте используются только умножение и сложение. Логарифмов нет.

Энтропия требует вычисления логарифма для каждой доли. На выборках в миллионы строк разница во времени накапливается. Индекс Джини работает быстрее. Качество разбиений на практике почти совпадает. Обе меры выбирают похожие пороги для числовых признаков и похожие разбиения для категориальных. Разница в итоговой точности модели обычно не превышает долей процента.

В библиотеке scikit-learn параметр criterion принимает значение gini по умолчанию. Если нужно воспроизвести поведение старых версий или сравнить с энтропией, передайте entropy. Для табличных задач с тысячами строк и десятками признаков разница в скорости обучения заметна. Качество остаётся на одном уровне.

Что такое отложенная выборка

Отложенная выборка это часть данных, которую не показывают модели во время обучения. Её используют чтобы оценить, как хорошо дерево обобщает закономерности на новых невиданных объектах, и понять какие поддеревья можно удалить без потери качества. Не путайте её с тестовой выборкой, которая используется только для финальной проверки готовой модели.

Представьте что вы обучаете дерево на данных о заявках по признакам дохода возраста числа открытых продуктов и даты последней покупки. Вы откладываете десять процентов строк до начала обучения. Дерево растёт глубоко и запоминает шум в обучающей части. На отложенной части качество падает. Это сигнал что некоторые ветви лишь подгоняются под случайные флуктуации. Вы проходите по узлам снизу вверх и проверяете: если удалить это поддерево и заменить его листом с большинством класса, качество на отложенной выборке не ухудшится, поддерево удаляют. Так получают более компактную модель которая лучше работает на новых данных.

Важно: отложенную выборку нельзя использовать для подбора гиперпараметров несколько раз. Каждый раз когда вы смотрите на её метрики и меняете решение, информация из неё утекает в модель. После нескольких итераций она перестаёт быть честной оценкой обобщения. В практике соревнований после каждого раунда старую тестовую выборку понижают в статус отложенной и берут свежую для финальной проверки.

Случайный лес и бэггинг

Бэггинг (bootstrap aggregating) это общий приём ансамблирования, применимый не только к решающим деревьям. Его суть в обучении нескольких моделей на разных бутстрэп-выборках: подвыборках исходной выборки того же размера, создаваемых случайным отбором объектов с возвращением. Из-за этого в одну бутстрэп-выборку попадают одни объекты по нескольку раз, а другие не попадают вообще. После обучения их предсказания объединяют голосованием большинства для классификации и усреднением для регрессии.

Связь бэггинга с разложением ошибки на смещение и разброс из главы 5 объясняет его эффективность для глубоких деревьев. У отдельного глубокого дерева смещение низкое, оно улавливает сложные границы между классами, но разброс очень высокий: небольшое изменение выборки сильно меняет его структуру. При обучении n независимых деревьев на разных бутстрэп-выборках дисперсия их среднего предсказания равна σ²/n, где σ², дисперсия предсказания отдельного дерева. Усреднение гасит разброс, а смещение ансамбля остаётся близким к смещению одного дерева и не может стать меньше него.

Обычный бэггинг для деревьев имеет недостаток: из-за использования всех признаков при разбиении деревья сильно коррелированы. Сильные признаки почти всегда выбираются для первых разбиений, поэтому структура деревьев отличается не сильно. Случайный лес решает эту проблему: на каждом разбиении узла признак выбирается из случайного подмножества, а не из всех доступных. Это убирает скрытую схожесть деревьев, дополнительно снижает разброс ансамбля и не даёт модели переобучаться даже при большой глубине отдельных деревьев.

Var(среднее из n оценок) = σ² / n, при условии независимости оценокВ этой формуле σ² обозначает дисперсию одной отдельной оценки, например предсказания дерева, обученного на бутстрэп-выборке, а n, количество таких оценок в ансамбле. Ключевое условие формулы, независимость оценок: если деревья коррелированы между собой, что почти всегда происходит из-за пересекающихся подвыборок одних и тех же данных, дисперсия среднего убывает медленнее, чем показывает эта формула, и эту проблему решает следующий приём.

Случайный лес строится на основе бэггинга деревьев решений, но добавляет приём, усиливающий эффект усреднения. Как и в обычном бэггинге, каждое дерево обучается на отдельной бутстрэп-выборке, случайной подвыборке исходных данных с возвращением. Но на каждом узле при выборе признака для разбиения алгоритм перебирает случайное подмножество признаков, а не все доступные. Для классификации обычно берут корень из общего числа признаков, для регрессии, примерно одну треть.

Этот приём нужен, даже если уже используются бутстрэп-выборки. Если в данных есть признак, который сильно превосходит остальные по полезности, почти каждое дерево леса выберет его для разбиения в корневом узле. В результате деревья получатся похожими, а выигрыш от усреднения зависит от независимости предсказаний: чем сильнее они коррелируют, тем меньше снижается разброс.

Случайное подмножество признаков на каждом узле разрывает скрытую схожесть между деревьями. На каждом шаге разбиения каждое дерево видит свой набор кандидатов, поэтому даже при обучении на похожих бутстрэп-выборках пути разбиения получаются разными. Усреднение предсказаний по-настоящему независимых деревьев снижает разброс сильнее, чем усреднение почти идентичных моделей, которые ошибаются в одном направлении.

Количество деревьев в лесу почти не создаёт риска переобучения, в отличие от глубины одного дерева. Глубокие неограниченные деревья склонны к переобучению, но при усреднении их ошибки компенсируют друг друга. На практике количество деревьев увеличивают до тех пор, пока хватает времени на обучение, заметного ухудшения качества на отложенной выборке от лишних деревьев обычно не происходит.

Что такое корреляция деревьев

Корреляция деревьев это мера того, насколько похожи ошибки разных моделей в ансамбле на одних и тех же объектах. Возьмём сквозной пример с классификацией заявок на кредит: если несколько решающих деревьев в ансамбле часто ошибаются на одних и тех же заявках, отклоняя одобрение у надёжных заёмщиков или одобряя заявки от рискованных клиентов, их корреляция считается высокой. В этом случае усреднение предсказаний таких деревьев почти не снижает общую ошибку системы, потому что все модели повторяют одни и те же недочёты.

Случайный лес уменьшает корреляцию деревьев за счёт ограничения набора признаков, которые можно использовать для разбиения на каждом узле. При построении каждого дерева модель не рассматривает все доступные признаки сразу, а случайно выбирает их подмножество. Для задачи с кредитными заявками это значит, что на одном узле дерево может проверять только доход заёмщика и число открытых продуктов, на другом только возраст и дату последней покупки, на третьем только доход и возраст. Из-за этого каждое дерево учится на разных сочетаниях признаков, их ошибки становятся менее похожими, а усреднение предсказаний даёт заметный выигрыш в точности по сравнению с одним деревом.

Откуда взята формула дисперсии среднего ансамбля

Формула, описывающая уменьшение разброса предсказаний при усреднении ответов нескольких моделей, работает только если ошибки отдельных моделей не связаны между собой. В этом случае случайные отклонения вверх и вниз компенсируют друг друга, и итоговый разброс получается заметно ниже, чем у отдельной модели. Если ошибки коррелированы, они часто складываются, а не компенсируются, поэтому уменьшение разброса происходит медленнее, чем предсказывает формула. Для снижения связи между отдельными деревьями в ансамбле используют случайный выбор признаков на каждом шаге разбиения узла.

Например, при построении моделей для классификации заявок на кредит на одобрение или отказ для первого дерева при разбиении корневого узла могут быть случайно выбраны только признаки дохода и числа открытых продуктов, а для второго дерева в аналогичном узле случайно попадут возраст и дата последней покупки. Из-за этого разные деревья учатся на разных зависимостях в данных, их ошибки становятся менее похожими друг на друга. При усреднении предсказаний таких деревьев случайные отклонения компенсируют друг друга эффективнее, и итоговый разброс ответа ансамбля получается ниже, чем при использовании всех признаков на каждом шаге. Этот приём не меняет принцип обучения каждого дерева по отдельности, но делает весь ансамбль устойчивее к шуму в исходных данных.

Градиентный бустинг

В случайном лесу деревья обучаются независимо друг от друга на разных бутстрэп-выборках, а их предсказания усредняются только после завершения обучения всех моделей. В градиентном бустинге (gradient boosting) деревья добавляются в ансамбль по очереди, и каждое новое дерево обучается на остатке, то есть разности между истинным значением и текущим предсказанием уже собранного ансамбля.

Рассмотрим работу алгоритма на примере задачи регрессии. Первым шагом алгоритм делает константное предсказание для всех объектов, обычно это среднее значение целевой переменной по всей обучающей выборке. Далее для каждого объекта вычисляется остаток: разность между истинным значением и текущим предсказанием ансамбля. На этих остатках обучается новое небольшое дерево, которое учится предсказывать именно эту разность. Его предсказание прибавляется к общему результату ансамбля с небольшим весом, который называют скоростью обучения (learning rate), обычно от 0.01 до 0.3. Малое значение этого параметра заставляет алгоритм делать маленькие шаги на каждой итерации, что снижает риск переобучения, но требует большего количества деревьев в ансамбле.

После добавления дерева процедура повторяется: вычисляются новые остатки с учётом предсказания добавленной модели, на них обучается следующее дерево, и его предсказание также прибавляется к общему результату с тем же значением скорости обучения. Такой цикл повторяется несколько сотен раз подряд, и на каждом шаге ансамбль исправляет ошибки, допущенные на предыдущих итерациях. В отличие от леса, где каждое дерево решает задачу самостоятельно, в бустинге каждое следующее дерево специализируется на исправлении ошибок уже собранного ансамбля, что позволяет достигать высокой точности на табличных данных при правильной настройке гиперпараметров.

Скорость обучения в градиентном бустинге определяет, насколько сильно каждое новое дерево влияет на текущую модель. При маленькой скорости, например 0,05 или 0,1, каждое дерево вносит лишь небольшую поправку в предсказания ансамбля. Чтобы достичь того же качества, что и при большой скорости, потребуется значительно больше деревьев. Однако этот подход обычно приводит к лучшей обобщающей способности модели, поскольку маленькие шаги сглаживают влияние случайного шума, который может быть усечён в отдельном дереве.

В отличие от случайного леса, где количество деревьев часто фиксировано или определяется эвристически, в бустинге число деревьев становится важным гиперпараметром, требующим осторожной настройки. Слишком большое число деревьев может привести к переобучению, когда модель начинает подгоняться под шум обучающей выборки, что особенно заметно на конечных этапах тренировки. Поэтому количество деревьев обычно ограничивают с помощью ранней остановки: обучение продолжается, пока метрика качества на отложенной выборке растёт, и прекращается, как только она перестаёт улучшаться.

Таким образом, бустинг управляет балансом смещения и разброса двумя параметрами одновременно, скоростью обучения и числом деревьев. Это напоминает подход из главы 5, где переобучение контролировалось глубиной одного дерева, но здесь возможности настройки становятся гибче. Маленькая скорость с большим числством деревьев часто даёт более устойчивые результаты, чем агрессивные поправки с малым количеством шагов, что делает бустинг универсальным инструментом для табличных данных, где важна точность и надёжность предсказаний.

Три популярные реализации

Три распространённые реализации градиентного бустинга. XGBoost, LightGBM и CatBoost. Все они реализуют одну и ту же идею последовательного исправления остатков, описанную в этом разделе: каждое новое дерево добавляется в ансамбль, чтобы компенсировать ошибки текущей модели. Разница между библиотеками лежит в основном в скорости обучения и удобстве работы с разными типами данных.

XGBoost, представленный в 2016 году Тяньци Ченом и Карлосом Гестрином, стал первым инструментом, массово популяризировавшим регуляризованный градиентный бустинг. Он использует эффективный алгоритм поиска разбиений узлов и долго оставался стандартом для соревнований по табличным данным.

LightGBM ускоряет обучение за счёт гистограммного поиска разбиений: все признаки предварительно группируются в ограниченное число корзин, что резко сокращает перебор порогов. Деревья в этой библиотеке растут по листьям, а не по уровням: очередной лист добавляется в то место дерева, где он даёт наибольший прирост качества.

CatBoost ориентирован на удобную работу с категориальными признаками без ручного кодирования. Он использует упорядоченный бустинг, который снижает утечку целевой переменной при подготовке признаков, что особенно полезно для данных с большим числом уникальных категорий.

Как обучение на остатке исправляет ошибки ансамбля

Остаток модели это разница между истинным значением цели и тем, что предсказала текущая композиция деревьев. В задаче классификации заявок на кредит цель принимает значение один для одобрения и ноль для отказа. Если ансамбль выдаёт вероятность 0.7 для клиента, которого на самом деле одобрили, остаток равен 0.3. Для отклонённого клиента с вероятностью 0.2 остаток равен минус 0.2.

Каждое следующее дерево обучается предсказывать эти остатки. Оно не пытается угадать исходную метку класса, а приближает нехватку текущего ансамбля. На первом шаге модель может предсказывать среднюю частоту одобрений по всей выборке. Остатки покажут, где эта константа ошибается сильнее всего. Второе дерево подстроится под эти ошибки, третье под ошибки первых двух и так далее.

После добавления нового дерева его предсказание умножается на коэффициент шага и прибавляется к сумме предыдущих. Остатки пересчитываются и становятся меньше по модулю. Процесс продолжается пока остатки не станут достаточно малыми или пока не будет достигнуто заданное число итераций. В коде это выглядит как последовательность вызовов fit на одном и том же наборе признаков, но с обновлённой целевой переменной на каждом шаге.

Важность признаков и её ловушки

Важность признака на основе снижения примеси суммирует, насколько сильно упало значение критерия разбиения, энтропии или индекса Джини, во всех узлах дерева, где этот признак использовался, взвешенно по доле объектов, прошедших через эти узлы. Для леса или бустинга эта сумма усредняется по всем деревьям ансамбля. В scikit-learn эта важность доступна сразу после обучения через атрибут feature_importances_ у обученной модели, без дополнительных вычислений, поэтому это самый распространённый способ на практике.

Альтернатива, важность по перестановке. Берётся уже обученная модель, один раз перемешывают значения одного признака случайным образом по всем объектам, оставляя остальные признаки как есть, и смотрят, насколько упадёт качество модели на отложенной выборке. Чем сильнее падение качества после перемешивания признака, тем этот признак важнее. В scikit-learn эту процедуру реализует функция permutation_importance.

При расчёте важности признака по снижению примеси вы столкнётесь с систематической ошибкой. Она завышает оценку для признаков с большим числом уникальных значений: непрерывных числовых признаков или категориальных с сотнями и тысячами значений. У таких признаков больше возможных порогов разбиения, поэтому дереву проще найти среди них удачное разбиение просто за счёт количества попыток. Даже если признак почти не связан с целевой переменной, он может получить высокую оценку важности только потому, что у него много вариантов для разделения данных.

Вторая ловушка касается любых способов оценки важности, не только основанных на снижении примеси. Если в данных есть два сильно скоррелированных признака, модель почти взаимозаменяемо использует их для разбиений. В результате важность делится между ними, и каждый получает среднюю оценку, хотя вместе они несут одну и ту же информацию. Удаление одного из таких признаков почти не влияет на качество модели, но по отдельности они выглядят полезными.

Следует учитывать, что оценка важности показывает, насколько признак помогал этой конкретной модели при обучении на этих конкретных данных. Это не доказательство причинно-следственной связи между признаком и целевой переменной. Высокая важность не гарантирует, что изменение значения признака приведёт к изменению предсказания модели в реальности. Например, признак «количество просмотров страницы товара» может иметь высокую важность в модели предсказания продаж, но это не значит, что увеличение просмотров напрямую повысит выручку, возможно, просто популярные товары и больше просматривают, и больше продают, а просмотры не служат их причиной.

Грабли · скоррелированные признаки делят важность

В таблице данных о клиентах банка часто встречаются два признака: площадь квартиры в квадратных метрах и оценочная стоимость этой квартиры. Это типичная ситуация при построении моделей для оценки платежеспособности клиентов. Эти признаки почти всегда сильно коррелированы: чем больше площадь, тем выше стоимость. При обучении решающего дерева, леса или градиентного бустинга модель может почти случайно чаще использовать для разбиений площадь. Тогда важность стоимости оказывается низкой. Аналитик может решить, что стоимость жилья не влияет на решение модели, и убрать этот признак. Но связанная с ним информация остаётся в модели через площадь, поэтому качество почти не меняется.

Прежде чем интерпретировать важность признаков, проверьте попарную корреляцию между ними. Сильно скоррелированную группу признаков стоит анализировать как единое целое. Отдельный разбор каждого признака в такой группе вводит в заблуждение и может привести к удалению полезных признаков.

Калибровка вероятностей

Калибровка вероятностей (probability calibration) это отдельный этап постобработки предсказаний модели, который приводит численные значения вероятностей в соответствие с реальной частотой событий. Модель считается откалиброванной, если среди всех объектов, которым она присвоила вероятность принадлежности к целевому классу около 0,7, реальная доля таких объектов действительно составляет примерно 70 процентов. Этот принцип работает для любого порогового значения: для 0,9 реальная доля должна быть около 90 процентов, для 0,2 около 20 процентов.

Часто точность самих решений модели и калиброванность её вероятностей не совпадают. Возьмём модель для оценки заявок на кредит, которая использует порог 0,5: все заявки с вероятностью выше этого значения относятся к классу «одобрить», ниже, к «отказать». Такая модель может почти никогда не ошибаться в разделении надёжных и ненадёжных заёмщиков, показывать высокую точность, полноту и F1 из главы 5. При этом все одобренные заявки могут получать вероятность 0,95, хотя реальная доля хороших заёмщиков в этой группе составляет только 80 процентов. В этом случае модель точна в своих решениях, но её численные вероятности не отражают реальную вероятность возврата кредита.

Калибровка затрагивает именно эти численные значения вероятностей, а не сами бинарные решения. Метрики классификации из главы 5, включая точность, полноту и F1, не позволяют понять, откалибрована модель или нет, потому что все они считаются после применения порога к вероятностям. Эти метрики оценивают только то, правильно ли модель разделила классы, но не то, насколько значение 0,7 из её предсказаний соответствует реальной частоте события в 70 процентов случаев.

Точность модели по классам не гарантирует, что выданные ей вероятности соответствуют реальным частотам событий. Чтобы проверить это, строят кривую надёжности, или калибровочную кривую. Для неё берут предсказания модели на отложенной тестовой выборке, разбивают все объекты на группы по значению предсказанной вероятности: например, от 0 до 0.1, от 0.1 до 0.2 и так далее до 1. Для каждой группы считают две величины: среднюю предсказанную моделью вероятность и реальную долю объектов с положительным классом среди всех элементов группы.

Эти две величины наносят на график: по горизонтали откладывают среднюю предсказанную вероятность, по вертикали реальную долю положительного класса. Идеально откалиброванная модель ложится точно на диагональ, проходящую от (0,0) до (1,1): в каждой точке предсказанная вероятность равна реальной доле. Если кривая отклоняется от диагонали, это показывает величину и направление ошибки калибровки в соответствующем диапазоне вероятностей. Например, если точка для интервала 0.7-0.8 лежит ниже диагонали, модель завышает вероятность для объектов, которые она считает с 70-80% шансом положительного класса.

Градиентный бустинг и случайный лес часто отклоняются от диагонали в сторону излишней уверенности. Бустинг подбирает последовательность деревьев так, чтобы минимизировать функцию потерь на обучающей выборке, и ради этого выталкивает предсказания к значениям 0 и 1 сильнее, чем оправдано реальными частотами. Усреднение предсказаний по листьям в лесу и бустинге вообще не гарантирует, что получившееся число имеет смысл частоты: это просто числовое значение, удобное для разделения классов, но не связанное напрямую с реальной вероятностью события.

Даже модель, точно предсказывающая класс, может выдавать вероятности, стремительно не совпадающие с реальными частотами событий. Кривая надёжности здесь показывает отклонение от пунктирной диагонали: точка вдоль оси X это сырой выход модели, точка по вертикали, доля объектов класса 1 среди всех объектов с таким выходом. Чем дальше кривая от диагонали, тем хуже калибровка.

Шкалирование Платта решает это простым способом. Поверх готовых предсказаний берут отложенную выборку и обучают логистическую регрессию с одним входом, сырым выходом исходной модели. Логистическая функция выучивает два числа: масштаб и сдвиг. Эти два параметра переводят сырой выход в вероятность. Метод работает, когда кривая надёжности отклоняется от диагонали S-образной искрой. Логистическая функция сама по себе S-образная, поэтому двумя параметрами может поправить форму.

Изотоническая регрессия, гибкая альтернатива. Вместо логистической функции она подбирает любую неубывающую по входу ступенчатую функцию. Никакой предположений о форме кривой. Справляется с искажениями любой сложности. Но за гибкость берёт данные. Чтобы не переобучиться на шуме отложенной выборки, нужна заметно большая выборка, чем для шкалирования Платта.

Оба метода обучаются на отдельной выборке. Она не участвовала в обучении модели. В scikit-learn оба доступны через CalibratedClassifierCV. Параметр method равный sigmoid выбирает шкалирование Платта, isotonic, изотоническую регрессию.

python
import numpy as np
from sklearn.datasets import make_classification
from sklearn.model_selection import train_test_split
from sklearn.ensemble import GradientBoostingClassifier
from sklearn.calibration import CalibratedClassifierCV, calibration_curve

X, y = make_classification(n_samples=5000, n_features=20, weights=[0.7, 0.3], random_state=0)
X_train, X_test, y_train, y_test = train_test_split(X, y, test_size=0.3, random_state=0)

base_model = GradientBoostingClassifier(random_state=0)
base_model.fit(X_train, y_train)

calibrated_model = CalibratedClassifierCV(
    GradientBoostingClassifier(random_state=0), method="isotonic", cv=5
)
calibrated_model.fit(X_train, y_train)

proba_raw = base_model.predict_proba(X_test)[:, 1]
proba_calibrated = calibrated_model.predict_proba(X_test)[:, 1]

frac_pos_raw, mean_pred_raw = calibration_curve(y_test, proba_raw, n_bins=10)
frac_pos_cal, mean_pred_cal = calibration_curve(y_test, proba_calibrated, n_bins=10)

print("предсказанная вероятность, до калибровки  ", np.round(mean_pred_raw, 2))
print("реальная доля положительных               ", np.round(frac_pos_raw, 2))
print("предсказанная вероятность, после калибровки", np.round(mean_pred_cal, 2))
print("реальная доля положительных               ", np.round(frac_pos_cal, 2))
Как строится калибровочная кривая

Калибровочная кривая, или кривая надёжности, это график, который показывает, насколько предсказанные моделью вероятности соответствуют реальной частоте события. По горизонтальной оси откладывают среднее значение предсказанной вероятности для сгруппированных объектов, по вертикальной оси - реальную долю объектов с положительным классом в той же группе. Пунктирная диагональ на таком графике соответствует идеальной калибровке: предсказанная вероятность в точности равна наблюдаемой частоте события.

Для моделей на основе решающих деревьев, в том числе для градиентного бустинга и случайного леса, калибровочная кривая часто имеет S-образную форму. Это значит, что модель систематически завышает вероятности в нижнем диапазоне и занижает их в верхнем. Например, при классификации заявок на кредит группа заявок с предсказанной вероятностью одобрения 15% может получить одобрение только в 7% случаев, а группа с предсказанной вероятностью 85% - в 93% случаев. Такая погрешность важна, если на основе вероятностей принимаются решения с учётом стоимости ошибок.

Метрики ранжирования MRR и NDCG

В главе 12 вы уже встречали MRR и NDCG как метрики качества поиска для систем RAG на уровне одного предложения. Здесь мы разбираем их формулы и числовые примеры.

Средний обратный ранг, Mean Reciprocal Rank, сокращённо MRR, считается так. Для одного запроса обратный ранг равен единице, делённой на позицию первого релевантного документа в выдаче. Обратный ранг никогда не превышает единицу: если правильный документ стоит первым, он равен единице, если вторым, одной второй, если пятым, одной пятой. MRR это среднее значение обратного ранга по набору из нескольких запросов. Метрика подходит, когда у запроса есть по сути один правильный ответ и важно, как быстро пользователь его найдёт, например при ответе на короткий фактический вопрос.

У MRR есть существенное ограничение. Она учитывает только позицию первого подходящего документа и не различает состав документов после него. Выдача с одним хорошим документом на первом месте и всем остальным нерелевантным получает такую же оценку, как выдача с одним хорошим документом первым и ещё четырьмя релевантными следом за ним. Это делает метрику неудобной для задач, где пользователю нужно несколько источников для ответа, например при составлении обзора по теме.

При оценке ранжирования у документов может быть несколько градаций релевантности, а не только два состояния: от 0, если документ не относится к теме запроса, до 3, если он полностью отвечает на вопрос пользователя. Для таких случаев используют нормализованный совокупный выигрыш NDCG, построенный на основе сырого совокупного выигрыша DCG.

DCG считается как сумма по всем позициям выдачи отношения релевантности документа на этой позиции к логарифму позиции по основанию 2, увеличенному на 1. Вклад каждого документа растёт с его релевантностью и падает с позицией в списке: документ с релевантностью 3 на первом месте даёт вклад 3, а на пятом месте примерно 1,16. Документы с релевантностью 0 не добавляют в сумму в любом случае.

Сырое значение DCG неудобно сравнивать между разными запросами, потому что оно растёт вместе с количеством релевантных документов, доступных для запроса. Поэтому DCG делят на идеальное значение IDCG, посчитанное для выдачи, где документы отсортированы по убыванию релевантности. Это отношение DCG к IDCG и есть NDCG, число от 0 до 1, где 1 означает идеальный порядок выдачи, а значения близкие к 0 говорят о том, что релевантные документы находятся в низких позициях или отсутствуют в выдаче.

DCG@k = сумма по позициям i от 1 до k из (2^rel_i - 1) / log2(i + 1)В формуле rel_i обозначает релевантность документа на позиции i, целое число не меньше нуля. Числитель 2^rel_i - 1 растёт быстро с ростом релевантности, поэтому документ с rel=3 вносит в DCG намного больше, чем документ с rel=1. Знаменатель log2(i+1), логарифмический штраф за позицию: на первом месте он равен 1, вклад документа не уменьшается, на пятой позиции он составляет около 2.585, и вклад того же по релевантности документа уменьшается в это число раз. NDCG@k получается делением DCG@k на IDCG@k. DCG тех же документов, отсортированных по убыванию релевантности. Полный числовой расчёт на пяти документах приведён в блоке ниже.
Вывод: расчёт NDCG на выдаче из пяти документов

Мы считаем NDCG@5 для конкретной выдачи поисковой системы на один запрос, состоящей из пяти документов на позициях с 1 по 5. Оценки релевантности заданы по шкале от 0 (документ не по теме) до 3 (документ отвечает на вопрос полностью). Система вернула документы в таком порядке релевантностей: позиция 1-3, позиция 2-1, позиция 3-2, позиция 4-3, позиция 5-0.

Сначала посчитаем выигрыш каждой позиции по формуле 2^{rel} - 1, где rel, оценка релевантности документа. Для нашей выдачи получаем: позиция 1: 2^3 - 1 = 7, позиция 2: 2^1 - 1 = 1, позиция 3: 2^2 - 1 = 3, позиция 4: 2^3 - 1 = 7, позиция 5: 2^0 - 1 = 0.

Далее посчитаем дисконт каждой позиции по формуле log2(pos + 1), где pos, номер позиции в выдаче. Получаем значения: позиция 1: log2(2) = 1, позиция 2: log2(3) ≈ 1.585, позиция 3: log2(4) = 2, позиция 4: log2(5) ≈ 2.322, позиция 5: log2(6) ≈ 2.585.

Теперь разделим выигрыш каждой позиции на её дисконт и сложим все пять слагаемых, это будет DCG фактической выдачи: 7/1 + 1/1.585 + 3/2 + 7/2.322 + 0/2.585 = 7.000 + 0.631 + 1.500 + 3.015 + 0.000 = 12.146.

Построим идеальную выдачу для тех же пяти документов: отсортируем их релевантности по убыванию, получится последовательность 3, 3, 2, 1, 0 вместо фактического порядка 3, 1, 2, 3, 0. Выигрыши для идеальной выдачи по позициям: 7, 7, 3, 1, 0.

Посчитаем DCG идеальной выдачи с теми же дисконтами по позиции: 7/1 + 7/1.585 + 3/2 + 1/2.322 + 0/2.585 = 7.000 + 4.416 + 1.500 + 0.431 + 0.000 = 13.347. Это значение IDCG, то есть наибольшее возможное DCG для данного набора из пяти документов при любом порядке их показа.

Разделим DCG фактической выдачи на IDCG идеальной выдачи: NDCG@5 = 12.146 / 13.347 ≈ 0.910. Эта выдача набрала 91 процент от максимально возможного дисконтированного выигрыша для этого набора документов, а потеря по сравнению с идеалом объясняется тем, что документ с релевантностью 3 стоит на четвёртой позиции вместо второй.

Что такое задача ранжирования

Задача ранжирования это упорядочивание объектов по степени релевантности запросу: например поисковых результатов или рекомендаций товаров. Обычные метрики классификации здесь не подходят, потому что важно не только правильно определить релевантный объект, но и на каком месте он стоит в выдаче. MRR и NDCG как раз оценивают качество этого упорядочивания.

RR@K, или reciprocal rank на K позициях, смотрит только на позицию первого релевантного документа в выдаче. Если этот документ находится на позиции rank в первых K местах, метрика равна 1/rank, иначе она равна 0. Например, если первый релевантный результат стоит на втором месте, значение метрики будет 0,5, если на пятом, 0,2, если нет релевантных документов в первых 10 позициях, значение будет 0. Это стандартная метрика точности для набора данных MS MARCO по методике Конференции по текстовому поиску при K=10.

NDCG@K, или нормализованный дисконтированный кумулятивный прирост, учитывает не только бинарную релевантность, но и её градации. Сначала считается кумулятивный прирост CG@K как сумма оценок релевантности всех документов в первых K позициях. Потом каждая оценка дисконтируется в зависимости от её позиции: чем выше позиция документа, тем меньше её вклад в итоговое значение. Формула дисконтированного прихода DCG@K выглядит так: сумма от i=1 до K от оценки релевантности i-го документа, делённой на логарифм по основанию 2 от i+1. Оценки релевантности могут принимать значения 0, 1, 2 или 3, где большее число означает более высокую релевантность. Чтобы сравнивать результаты разных запросов, DCG@K нормализуют, деля на идеальный DCG@K, который получается при сортировке всех документов по убыванию релевантности. Это стандартная метрика точности для набора данных MS MARCO TREC при K=10.

Главное отличие метрик в том, что RR@K оценивает только положение первого релевантного документа, а NDCG@K учитывает релевантность всех документов в выдаче и их порядок, поэтому подходит для задач, где релевантность имеет разные степени, а не только два значения.

Практический выбор между бустингом и нейросетью

Выбор между градиентным бустингом и нейросетью для табличных данных определяется контекстом задачи, а не моделями. Три параметра задают границы. Тип входных данных. Объём выборки. Требования к интерпретируемости и ресурсам команды.

За градиентным бустингом стоит идти, если признаки уже лежат в строках таблицы. Числа, коды, one-hot векторы, признаки, вычисленные из логики приложения. Если внутри строк нет изображений, аудиосигналов или текста, которые требуют свёрточных или рекуррентных слоёв. Выборка от нескольких тысяч до нескольких миллионов строк. В этом диапазоне бустинг работает стабильно и не требует гиперпараметрического поиска, сопоставимого с подбором архитектуры нейросети.

Если нужно быстро объяснить, почему модель сделала конкретное предсказание, бустинг выигрывает. Инструменты вроде важности признаков или SHAP работают на решающих деревьях и их ансамблях без дополнительных слоёв абстракции. Бюджет на инфраструктуру минимален. Достаточно scikit-learn или lightgbm. Команде не нужно разворачивать GPU-ферму, отслеживать версии фреймворков или поддерживать среду для экспериментов с нейросетями.

За нейросетью стоит идти, когда сырые данные имеют пространственную или последовательную структуру. Изображения, текст, звук, временные ряды. Главы 20 по 30 раскрывают, как нейросеть выучивает локальные паттерны и долгосрочные зависимости, которые не задать вручную через инженерию признаков. Очень большая выборка, десятки миллионов строк и больше. Нейросеть успевает выучить сложные взаимодействия признаков сама, без ручного перебора комбинаций.

Если часть входа это уже готовые эмбеддинги или выход другой нейросети, естественно продолжать дифференцируемым слоем поверх них. Просто добавьте слой полносвязных пропусков и обучите конечный классификатор или ранжировщик. Тогда вы не тратите время на переобучение всей системы с нуля.

На практике градиентный бустинг и нейросети дополняют друг друга, а не заменяют. Частый рабочий приём: взять эмбеддинги из готовой нейросети, например эмбеддинги текста отзыва клиента, и подать их как дополнительные табличные признаки в градиентный бустинг вместе с обычными числовыми и категориальными столбцами. Так вы забираете сильные стороны обеих моделей: нейросеть эффективно извлекает смысл из неструктурированных данных, а бустинг точно работает с уже подготовленными табличными признаками, не требует сложной настройки архитектуры и устойчив к переобучению при стандартном наборе гиперпараметров.

Итоговое практическое правило простое. Если у вас табличные данные и задача новая, начинайте с градиентного бустинга. Он обучается за минуты, почти не требует подбора архитектуры и часто сразу даёт качество, достаточное для первой рабочей версии. Переход к нейросети имеет смысл обсуждать только тогда, когда после подбора гиперпараметров бустинга остаётся зазор в качестве, который он не закрывает даже при использовании кросс-валидации для выбора лучшей конфигурации.

from sklearn.tree import DecisionTreeClassifier

forest = models["случайный лес"].fit(X, y)
importances = forest.feature_importances_

Третий параметр выбора между бустингом и нейросетью

Третий ключевой параметр выбора модели это требование к интерпретируемости результата. В задаче классификации заявок на кредит часто нужно не только получить предсказание одобрения или отказа, но и объяснить его заявителю или регулятору. Градиентный бустинг на основе решающих деревьев позволяет легко отследить, какие признаки повлияли на решение больше всего: например, если доход заявителя ниже установленного порога или число открытых банковских продуктов превышает допустимое значение, это можно показать напрямую. Нейросеть в таком случае обычно является чёрным ящиком: даже при высокой точности предсказаний проследить путь, по которому она пришла к конкретному решению, практически невозможно.

При небольших табличных выборках с простой структурой признаков бустинг часто даёт достаточное качество за значительно меньшее время обучения. Если же объём данных большой, а в строках присутствуют текстовые описания или временные ряды, нейросеть может показать выше точность, но придётся мириться с отсутствием простого объяснения каждого отдельного решения.

Коротко

  1. Табличные данные редко имеют пространственную или последовательную структуру, которую могут использовать свёртка и внимание, поэтому решающие деревья и их ансамбли на таких данных часто выигрывают у нейросетей при меньшей выборке и без дополнительной подготовки признаков.
  2. Решающее дерево строится жадным способом: на каждом шаге алгоритм выбирает разбиение с наибольшим приростом информации, который считается как энтропия узла минус взвешенная энтропия потомков, а без ограничения глубины или обрезки дерево переобучается вплоть до заучивания шума обучающей выборки.
  3. Случайный лес усредняет много деревьев, обученных на разных бутстрэп-выборках и на разных случайных подмножествах признаков на каждом разбиении, дисперсия среднего падает с числом независимых деревьев, а случайный выбор признаков разрывает их скрытую схожесть.
  4. Градиентный бустинг добавляет деревья по очереди, каждое новое дерево обучается на остатке текущего ансамбля, а скорость обучения и число деревьев вместе управляют балансом между недообучением и переобучением.
  5. Важность признаков показывает вклад в разбиения конкретной обученной модели, она не совпадает с причинной связью с целевой переменной, завышена у признаков с большим числом уникальных значений и делится между сильно скоррелированными признаками.
  6. Точная модель может быть плохо откалибрована, кривая надёжности выявляет расхождение между предсказанной вероятностью и реальной частотой, а шкалирование Платта и изотоническая регрессия исправляют это отдельным шагом поверх обученной модели, MRR оценивает позицию первого верного ответа, а NDCG учитывает степень релевантности каждого документа во всей выдаче.

1. Ваша команда прогнозирует отток клиентов банка по 40 табличным признакам: возраст, доход, число продуктов, история звонков в поддержку. Строк 8000. Коллега предлагает сразу обучить трансформер на этих признаках вместо градиентного бустинга. Что говорит против этой идеи в первую очередь?

Правильный вариант верен по двум причинам. Во-первых, трансформер рассчитан на последовательности или графы, а табличные признаки это просто набор столбцов без заранее заданного порядка или связей между ними. Архитектура не получит никакой выгоды от такой структуры. Во-вторых, 8000 строк это очень мало для трансформера, который имеет миллионы параметров и требует десятков тысяч примеров для стабильного обучения. Остальные варианты неверны. Трансформеры могут принимать числа, их просто нормируют или встраивают. Проблема с памятью ноутбука не фундаментальна, модель можно обучать на сервере. Утверждение, что бустинг всегда точнее, ложно, точность зависит от данных и задачи.

2. В узле дерева 20 объектов, 10 класса A и 10 класса B, энтропия узла H = 1.0 бита. После разбиения на два равных по размеру потомка, по 10 объектов в каждом, энтропия каждого потомка равна 0.9 бита. Чему равен прирост информации этого разбиения?

Правильный ответ: 0.1 бита. Прирост информации вычисляется как разность энтропии родительского узла и взвешенной суммы энтропий потомков. Здесь взвешенная энтропия потомков равна 0.5*0.9 + 0.5*0.9 = 0.9 бита, поэтому 1.0 - 0.9 = 0.1 бита. Вариант 0.0 бита неверен, так как энтропия потомков меньше родительской, значит разбиение даёт выигрыш. Вариант 0.9 бита соответствует взвешенной энтропии потомков, а не приросту. Вариант 1.0 бита равен энтропии родительского узла, что было бы только если энтропия потомков была нулевой.

3. В случайном лесу на каждом узле каждого дерева алгоритм ограничивает поиск лучшего порога случайным подмножеством признаков. Зачем нужен этот приём, если бэггинг, обучение каждого дерева на своей бутстрэп-выборке, уже есть?

Правильный ответ верен, потому что ограничение подмножества признаков снижает корреляцию между деревьями леса. Без этого приёма сильные признаки делают деревья похожими, а усреднение коррелированных оценок почти не уменьшает разброс. Первый вариант неверен: приём не только ускоряет обучение, но и снижает корреляцию деревьев, улучшая качество ансамбля. Второй вариант неверен, так как для категориальных признаков есть отдельные механизмы. Третий вариант неверен, так как бутстрэп-выборки и ограничение подмножества признаков дополняют друг друга.

4. Вы обучили случайный лес и градиентный бустинг на одних данных с одинаковым числом деревьев. У леса при добавлении новых деревьев риск переобучения почти не растёт. У бустинга же после определённого числа деревьев качество на отложенной выборке начинает падать. Чем объясняется эта разница?

Правильный ответ верен: в случайном лесе деревья обучаются независимо, их предсказания усредняются, поэтому добавление новых деревьев почти не повышает риск переобучения. В градиентном бустинге каждое следующее дерево исправляет остатки предыдущих и со временем подстраивается под шум в данных, из-за чего качество на отложенной выборке может падать. Остальные варианты неверны: глубина деревьев в обоих алгоритмах настраивается отдельно, это не причина разницы; бустинг не использует нейросети внутри деревьев, это обычные решающие деревья; ограничение признаков на разбиении в лесе служит для уменьшения корреляции оценок, но не связано с ростом переобучения при увеличении числа деревьев.

5. Модель кредитного скоринга правильно относит 92 процента заявок к «одобрить» или «отказать» по порогу 0.5, точность из главы 5 высокая. При этом среди заявок с предсказанной вероятностью одобрения около 0.9 реальная доля одобренных исходов составляет только 70 процентов. Что это означает?

Правильный ответ верен, потому что точность из главы 5 считается после применения порога к вероятностям, а калибровка отдельно проверяет, совпадают ли предсказанные вероятности с реальными долями исходов. Высокая пороговая точность не гарантирует калиброванность, поэтому остальные варианты неверны: ситуация возможна, 92% точности не означают калиброванность, и переобучение с нуля не требуется, достаточно откалибровать модель.

6. Поисковая система для юридических документов возвращает документы с оценкой релевантности от 0 до 3, часть документов отвечает на вопрос частично, часть полностью. Какая метрика лучше учитывает эту разницу в степени релевантности между документами выдачи?

Верный ответ NDCG. Эта метрика напрямую учитывает градацию релевантности документов в выдаче, используя для каждой позиции вес 2 в степени rel минус 1, где rel это оценка релевантности документа. Остальные варианты не подходят: MRR учитывает только позицию первого релевантного документа и не различает степени релевантности, recall@k считает только количество релевантных документов в топ-k без учёта их оценки, F1-мера предназначена для бинарной классификации и не работает с градациями релевантности в задачах ранжирования.
