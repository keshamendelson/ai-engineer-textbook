Когда действий слишком много, чтобы их перечислить

В Q-обучении, описанном в главе 36, выбор действия в состоянии s сводится к поиску argmax по функции ценности Q(s,a) среди всех допустимых действий a. Для простого окружения, где пингвин на льду может двигаться только в четырёх направлениях, это перебор четырёх чисел, который занимает доли миллисекунды. Первый случай, когда такой перебор перестаёт быть дешёвым, возникает, когда действий формально конечное число, но их очень много. Например, при генерации текста языковой модели на каждом шаге нужно выбрать следующий токен из словаря размером в несколько десятков тысяч вариантов. Вычисление Q(s,a) для каждого такого токена на каждом шаге генерации уже заметно увеличивает задержки.

Второй, более жёсткий случай, возникает, когда действия непрерывны. Например, при управлении роботом действием может быть угол поворота руля или крутящий момент мотора, и таких действий бесконечно много. В этой ситуации поиск argmax по Q(s,a) требует запуска отдельной процедуры оптимизации на каждом шаге взаимодействия с окружением вместо простого перебора. Оба эти случая объединяет одна общая проблема: оценивать ценность каждого отдельного действия становится слишком дорого или вовсе невозможно. Это ограничение подталкивает к отказу от попытки оценить каждое действие по отдельности и переходу к прямой параметризации стратегии, когда выбор действия описывается функцией, которую можно оптимизировать напрямую.

Когда пространство действий слишком велико или непрерывно, подход из главы 36 с отдельной оценкой ценности для каждого возможного действия перестаёт работать. Вместо этого используют стратегию, параметризованную напрямую весами нейросети θ: функция π_θ(a|s) берёт на вход состояние s и сразу выдаёт распределение вероятностей по всем действиям a, без предварительного подсчёта отдельной ценности для каждого варианта. Для дискретных пространств действий выход сети проходит через softmax по конечному числу нейронов, что даёт корректное распределение на множестве доступных действий. Для непрерывных пространств сеть выводит параметры распределения, например среднее и дисперсию нормального распределения, из которого затем сэмплируют конкретное действие. Ключевое следствие такого подхода: выбор действия на каждом шаге превращается в сэмплирование из вывода сети, а не в перебор всех вариантов или поиск argmax. Размер и структура пространства действий больше не ограничивают вычислительные затраты на этапе выбора действия.

Цель обучения такой стратегии формулируется просто: подобрать такие значения θ, чтобы ожидаемая отдача при следовании стратегии π_θ в среде была максимальной. Ожидаемая отдача считается как среднее суммарной награды по всем возможным траекториям работы стратегии. Дальше в этой главе выводится, как именно эту цель превратить в шаг градиентного подъёма по параметрам θ, и сам этот вывод называется теоремой о градиенте по стратегии. Полученная формула лежит в основе всех последующих методов, которые рассматриваются в главе: от базовой REINFORCE до алгоритмов с базовой линией, критиком и обрезкой отношения в PPO, а также их адаптации для языковых моделей в RLHF и GRPO.

Как получается формула REINFORCE

J(θ) = E[R(τ)], τ ~ π_θJ(θ), целевая функция обучения, которую нужно максимизировать. Она показывает ожидаемую суммарную отдачу при запусках эпизодов по текущей стратегии π_θ. τ, траектория, последовательность состояний и действий за эпизод, R(τ), её суммарная отдача, как в главе 36. Вся дальнейшая математика раздела нужна для ответа на один вопрос: в какую сторону изменить параметры θ, чтобы значение J(θ) выросло.

Цель обучения стратегии π_θ, максимизировать функционал J(θ) = E_{τ~π_θ}[R(τ)], где τ обозначает траекторию, а R(τ), суммарную награду, полученную при её прохождении. Каждое действие a на шаге t это сэмпл из распределения π_θ(a|s), а сэмплирование не дифференцируемая операция. Обратное распространение ошибки из главы 4 работает только с детерминированными вычислениями, поэтому напрямую продифференцировать J(θ) по параметрам θ стратегии не получается.

Наивная попытка расписать J(θ) как сумму по всем возможным траекториям с их вероятностями тоже приводит в тупик. Полученное выражение содержит градиент вероятности траектории, а это уже не вероятность, поэтому оценить его прямым усреднением по сэмплам из π_θ невозможно. Мы не можем посчитать градиент ожидания награды напрямую через обычные сэмплы из текущей стратегии.

Выход из этого тупика, стандартный приём из математической статистики, логарифмическая производная. Он позволяет переписать градиент вероятности траектории в виде суммы логарифмов вероятностей выбранных действий, что уже можно оценить по сэмплам из π_θ. Полный вывод формулы REINFORCE с использованием этого приёма приведён в раскрывающемся блоке ниже.

Итог вывода оказывается на удивление простым: направление обновления параметров стратегии θ вычисляется как сумма градиентов логарифма вероятности каждого действия a_t, выбранного в состоянии s_t на шаге t эпизода, причём каждый такой градиент умножается на общую для всего эпизода отдачу G. На практике это означает, что если эпизод в среднем завершился с высокой отдачей, стратегия немного повышает вероятность всех действий, которые в нём встречались, а если отдача низкая, вероятность этих действий немного понижается, и для этого не нужно знать детали переходов среды.

Прямое дифференцирование целевой функции обучения стратегии не работает, потому что это матожидание отдачи по траекториям, а выбор действий в стратегии дискретный: мы не можем просто взять производную по параметрам θ от операции выбора действия a_t ~ π_θ(a_t|s_t).

Теорема о градиенте по стратегии позволяет обойти эту проблему: она показывает, что градиент матожидания отдачи по параметрам стратегии равен матожиданию градиента логарифма вероятности выбранных действий, умноженного на соответствующую отдачу. Если мы оцениваем это значение по нескольким эпизодам, запущенным в среде, получаем формулу REINFORCE: для каждого шага каждого эпизода мы считаем градиент log π_θ(a_t|s_t), умножаем на отдачу этого эпизода и усредняем по всем наблюдениям, после чего делаем шаг градиентного подъёма в полученном направлении.

Вывод: как из ожидания получается формула REINFORCE

Цель обучения стратегии записывается как J(θ) = E_{τ~π_θ}[R(τ)], где τ это траектория, R(τ) её суммарная отдача, а ожидание берётся по всем траекториям, которые порождает стратегия с параметрами θ.

Это ожидание можно раскрыть как сумму по всем возможным траекториям: J(θ) = Σ_τ P(τ|θ)·R(τ), где P(τ|θ) это вероятность того, что стратегия с параметрами θ породит именно траекторию τ.

Если попытаться продифференцировать это выражение напрямую, получим ∇_θJ(θ) = Σ_τ ∇_θP(τ|θ)·R(τ). Этим выражением нельзя пользоваться как есть: ∇_θP(τ|θ) сама по себе не вероятность, поэтому эту сумму нельзя оценить, просто усредняя по траекториям, сэмплированным из π_θ.

Применим тождество логарифмической производной: ∇_θ log f(θ) = ∇_θf(θ)/f(θ), откуда ∇_θf(θ) = f(θ)·∇_θ log f(θ). Подставим f(θ) = P(τ|θ): получим ∇_θP(τ|θ) = P(τ|θ)·∇_θ log P(τ|θ).

Подставим это обратно в градиент цели: ∇_θJ(θ) = Σ_τ P(τ|θ)·∇_θ log P(τ|θ)·R(τ) = E_{τ~π_θ}[∇_θ log P(τ|θ)·R(τ)]. Это снова ожидание по траекториям из π_θ, значит, его можно оценить усреднением по сэмплированным траекториям.

Раскроем P(τ|θ) по шагам эпизода: P(τ|θ) = p(s0)·Π_t π_θ(a_t|s_t)·P(s_{t+1}|s_t,a_t). Возьмём логарифм произведения: log P(τ|θ) = log p(s0) + Σ_t log π_θ(a_t|s_t) + Σ_t log P(s_{t+1}|s_t,a_t).

Первое и третье слагаемые описывают устройство среды и не зависят от θ, поэтому их градиент по θ равен нулю: ∇_θ log P(τ|θ) = Σ_t ∇_θ log π_θ(a_t|s_t). В формуле не осталось вероятностей переходов среды, которые почти всегда неизвестны.

Итог, теорема о градиенте по стратегии: ∇_θJ(θ) = E_τ[Σ_t ∇_θ log π_θ(a_t|s_t)·R(τ)]. REINFORCE (Williams, 1992) оценивает это по N сэмплированным траекториям и делает шаг θ ← θ + α·(среднее по выборке). На практике R(τ) на шаге t заменяют отдачей с этого шага и до конца эпизода G_t, потому что действие не может повлиять на уже полученные награды: ∇_θJ(θ) = E[Σ_t ∇_θ log π_θ(a_t|s_t)·G_t].

Аналогия

Представьте игрока, который перебирает лотерейные билеты вслепую и запоминает только итоговый выигрыш или проигрыш за весь вечер. Он не знает, какой именно билет дал результат, если таковой был.

После неудачного вечера он чуть реже берёт билеты тех видов, которые покупал в этот раз, а после удачного чуть чаще. При этом он не может точно определить, какой из билетов сыграл решающую роль.

REINFORCE действует похожим образом. У него нет возможности заглянуть внутрь среды и понять, какое из действий эпизода привело к хорошей или плохой отдаче. Поэтому он одинаково повышает или понижает вероятность всех действий эпизода на одну и ту же величину, пропорциональную итоговой отдаче.

Именно эта грубость оценки и есть источник проблемы, к которой переходит следующий раздел.

Высокая дисперсия оценки и что с ней делают

В обучении с подкреплением есть три типичные причины, из-за которых оценка градиента получается очень шумной. Возьмём пример шахматной партии. Первая: награда разрежена и приходит только в конце партии, когда вы узнаёте, выиграли вы или проиграли. Вторая: эта награда смещена по времени относительно решающих ходов, сделанных десятками ходов раньше. Третья: среда стохастична, поэтому неясно, был ли конкретный ход хорошим или просто повезло с ответом соперника.

Метод REINFORCE страдает от всех трёх причин сразу. В его формуле одна итоговая отдача G умножается на градиент логарифма политики log π для каждого действия в эпизоде. Из-за этого один случайно удачный или неудачный эпизод резко меняет оценку градиента для каждого действия в нём. Следующий сэмплированный эпизод с теми же действиями может дать совершенно другую отдачу из-за случайности среды, поэтому оценки градиента сильно разбросаны.

Тот же эффект проявляется при обучении языковых моделей. Если вы оцениваете целый сгенерированный ответ одним числом в конце, разреженность награды и смещение по времени встают в полный рост. Неясно, какой именно токен в ответе повлиял на итоговую оценку, а случайность генерации может сделать одинаковые ответы получить совершенно разные награды.

Оценка градиента в REINFORCE получается очень шумной. Агент делает случайные пробы, и одна и та же стратегия даёт разбросанные по величине отдачи. Чтобы обучение сходилось, дисперсию оценки нужно снижать.

Для этого вводят базовую линию (baseline). Это функция b(s_t), которая зависит только от состояния s_t на шаге t, но не от выбранного действия. Из полной отдачи G_t на каждом шаге вы можете вычесть такую базовую линию. Математическое ожидание градиента при этом не изменится. Вклад добавки b(s_t) в среднем равен нулю, так как она не коррелирует с вероятностью действия в текущей стратегии.

Интуиция простая. Допустим, типичная отдача из состояния s всегда около 1000. Сырое значение G_t=1005 выглядит как большое число. Оно даёт градиенту большой и шумный шаг, хотя по сути отдача лишь чуть выше средней. После вычитания базовой линии, близкой к 1000, та же ситуация превращается в скромную поправку +5. Шаг становится осмысленным, а случайные всплески отдачи перестают так сильно раскачивать веса.

В качестве базовой линии чаще всего берут саму функцию ценности состояния V(s) из главы 36. Она уже отвечает ровно на вопрос, какая отдача типична из этого состояния. Такую функцию обучают отдельной небольшой сетью, которая предсказывает V(s_t) по наблюдаемым траекториям. Разность G_t и V(s_t) называют преимуществом (advantage). Она показывает, насколько конкретное действие лучше или хуже обычного для этого состояния.

A(s_t, a_t) = Q(s_t, a_t) - V(s_t)Разность Q(s_t,a_t) - V(s_t) называют преимуществом (advantage). Q(s_t,a_t), ожидаемая отдача от конкретного действия a_t в состоянии s_t, а V(s_t), средняя ожидаемая отдача из этого состояния по всем возможным действиям. Формула REINFORCE с базовой линией заменяет кумулятивную отдачу G_t на оценку этого преимущества A(s_t,a_t), и именно эту величину умножают на градиент log π_θ(a_t|s_t) при обновлении параметров стратегии.
Числа: базовая линия на практике

Возьмём конкретный пример. В одном состоянии среды отдачи трёх сэмплированных действий равны 990, 1005 и 1015, а критик оценивает V(s) = 1000. Без базовой линии веса градиента равны самим отдачам: 990, 1005, 1015. Все они близки к 1000, разница между худшим и лучшим всего 25, поэтому почти не видно, что одно действие хуже среднего, а два других лучше.

С базовой линией вычитаем 1000 из каждой отдачи. Получаем веса -10, +5, +15. Относительный порядок действий и разница их качества видны сразу: худшее получает отрицательный вес, лучшее, значительно положительный.

При усреднении по большому количеству состояний среднее поправок остаётся около нуля. Базовая линия не смещает оценку градиента, но сильно снижает её дисперсию: веса распределены вокруг нуля, а не сгруппированы около большого общего значения.

Актор и критик, две сети с разными задачами

Архитектура актор-критик появляется как практическое решение проблемы базовой линии из предыдущего раздела: вместо того чтобы вычислять её каждый раз заново по собранным траекториям, мы храним её в отдельной нейросети, обученной параллельно с основной моделью. В этой схеме две сети выполняют разные задачи. Актор это та же сеть политики π_θ(a|s), которую мы выводили при обсуждении формулы REINFORCE: она выбирает действия в состояниях и обучается по градиенту по стратегии, но вместо сырой накопленной отдачи на траектории использует оценку преимущества, построенную на базовой линии.

Вторую сеть называют критиком. Это отдельная модель V_φ(s) с собственными весами φ, которая не выбирает действия вообще. Её единственная задача предсказывать ожидаемую отдачу, которую актор получит, начиная с данного состояния s, если будет следовать текущей политике. По сути критик делает то же, что Q-обучение из главы 36 делало для пар состояние-действие, только теперь его оценка относится к одним состояниям, без привязки к конкретному действию. Имя «критик» выбрано не случайно: эта сеть оценивает, насколько хорошо выступил актор в каждом встреченном состоянии, и её прогноз становится базовой линией, по которой корректируется обучение политики.

На одном шаге обучения актор и критик выполняют разные задачи, но их результаты сразу используются для обновления обеих сетей. Критик обучается по правилам регрессии с учителем, которые вы уже знаете из главы 2: его цель, предсказать значение состояния V_φ(s_t), а метка для этого предсказания это бутстрэп-оценка r_{t+1} + γ·V_φ(s_{t+1}), построенная по принципу временной разности, знакомому вам по Q-обучению из главы 36. Функция потерь критика это квадрат разности между этой бутстрэп-оценкой и текущим предсказанием сети. Полученная оценка значения состояния сразу используется для расчёта преимущества на шаге t: A_t = r_{t+1} + γ·V_φ(s_{t+1}) - V_φ(s_t). Именно это число, а не сырая кумулятивная отдача G_t, подставляется в формулу градиента по стратегии при обновлении весов актора.

Важно, что градиенты актора и критика текут по совершенно разным путям и никогда не смешиваются на одном шаге. При обновлении весов актора значение A_t считается фиксированной константой, через которую не пропускается обратное распространение ошибки к весам критика. Это позволяет настраивать обе сети независимо: например, обновлять критика несколько раз подряд на новых собранных данных, а актора, реже, чтобы избежать больших скачков стратегии. В этой связке методы на основе ценности из главы 36 и методы на основе стратегии из текущей главы дополняют друг друга, не теряя своих отдельных преимуществ.

На практике одна сеть с двумя головами

На практике актор и критик почти никогда не реализуют как полностью раздельные сети с нуля. Чаще берут один общий ствол: все слои трансформера или свёрточной сети, а сверху ставят две небольшие головы. Одна имеет выход по числу действий для актора, другая выдает одно скалярное значение для критика.

Такой подход снижает вычислительные затраты: общий ствол считается один раз за шаг вместо двух. Признаки, полезные для оценки ценности состояния, зачастую пересекаются с признаками, полезными для выбора действия. Для языковых моделей это особенно важно из-за большого размера самой сети. К вопросу потребления памяти мы вернёмся в разделе, где переносим всю эту технику на генерацию текста.

PPO и ограничение шага обучения

Размер шага градиентного подъёма для стратегии требует особой осторожности. В отличие от обычного обучения с учителем из главы 2, где работает фиксированная выборка, в обучении с подкреплением данные для следующего шага генерит сама текущая стратегия. Один неудачный шаг оптимизации в обучении с учителем портит качество на текущей выборке, но на следующем шаге её можно пересчитать теми же данными. Слишком большой шаг в обучении с подкреплением способен резко испортить π_θ. Тогда все последующие траектории сэмплируются уже из испорченной стратегии. Восстановиться из этой точки может быть сложнее, чем начать обучение с нуля.

Актор-критик из предыдущего раздела снижает дисперсию оценки выигрыша за счёт введения отдельной сети для оценки состояний. Он не ограничивает размер самого шага обновления стратегии. Потребуется отдельный механизм, который прямо запрещает стратегии сдвигаться слишком далеко за одно обновление. PPO, или Proximal Policy Optimization, один из самых распространённых таких механизмов. Schulman и соавторы представили его в 2017 году.

Идея PPO строится на отношении вероятностей. Для каждого действия вычисляется отношение вероятности новой стратегии к вероятности старой. Если это отношение отклоняется от единицы больше заданного порога ε, прибыль обрезается. Клиппированная функция потерь не даёт градиенту быть слишком большим. Стратегия остаётся близкой к предыдущей версии. Обучение становится стабильнее, и агент не теряет уже приобретённые навыки.

Чтобы отслеживать, насколько сильно стратегия изменилась с момента сбора данных для текущего обновления, вводят отношение вероятностей r_t(θ) = π_θ(a_t|s_t) / π_{θ_old}(a_t|s_t). Здесь θ_old, параметры, под которыми собраны все пары состояние-действие, а θ, параметры, которые оптимизатор меняет прямо сейчас. Если r_t(θ) = 1, вероятность действия не изменилась. При r_t(θ) > 1 действие стало более вероятным под новыми параметрами, чем при сборе данных, а при r_t(θ) < 1, менее вероятным.

Наивная реализация градиента по стратегии использует оценку r_t(θ) * A_t, где A_t, преимущество действия a_t, рассчитанное по данным, собранным под θ_old. В этом произведении нет ограничений на значение r_t(θ): за один шаг оптимизатора оно может сколь угодно сильно отойти от единицы, что приводит к резкому изменению стратегии, нестабильному обучению и падению качества сгенерированных ответов.

Именно эту проблему решает клиппированная выгода в алгоритме PPO. Она ограничивает значение r_t(θ) узким диапазоном вокруг единицы, чтобы шаг обновления не был слишком большим. Точный механизм работы клиппированной выгоды разбирается в раскрывающемся блоке ниже.

r_t(θ) = π_θ(a_t|s_t) / π_θ_old(a_t|s_t)Числитель формулы, вероятность действия a_t в состоянии s_t при текущих обновляемых параметрах θ. Знаменатель, вероятность того же действия в том же состоянии при старых параметрах θ_old, под которыми собрали данные для этого шага обучения. Отношение этих двух величин показывает, во сколько раз модель стала чаще или реже выбирать данное действие после обновления параметров.
L^CLIP(θ) = E_t[ min( r_t(θ)·A_t, clip(r_t(θ), 1-ε, 1+ε)·A_t ) ]Формула считает ожидание по шагам. r_t(θ) это отношение вероятностей новой и старой стратегий. clip(r_t(θ), 1-ε, 1+ε) держит отношение в границах от 1-ε до 1+ε, ε берут около 0.2, внутри границ значение не трогает. min берёт меньшее из обычной выгоды и клиппированной. Минимум делает оценку пессимистичной, не завышает выгоду от шага. Разбор по значениям r_t(θ) ниже.
Разбор: что клиппирование делает при разных r

В обучении с подкреплением большой шаг обновления политики опаснее, чем в обучении с учителем: новое распределение действий сразу используется для сбора следующих данных, и резкое изменение параметров может привести к катастрофическому забытию ранее изученных полезных стратегий. Чтобы ограничить величину шага, алгоритм PPO вводит клиппирование отношения вероятностей действий в новой и старой политике.

При значении ε = 0.2 диапазон клиппирования составляет [0.8, 1.2]. Функция потерь PPO для одного действия записывается как L = min(r_t · A_t, clip(r_t, 0.8, 1.2) · A_t), где r_t, отношение вероятности действия в текущей политике к вероятности этого же действия в политике перед обновлением, а A_t, преимущество действия на шаге t.

Рассмотрим случай положительного преимущества A_t = +1, когда действие полезное. При r_t = 1.0 вероятность действия не изменилась: неклиппированное значение равно 1.0 · 1 = 1.0, клиппированное clip(1.0, 0.8, 1.2) · 1 = 1.0, минимум из двух значений составляет 1.0. Если r_t = 1.15, значение ещё находится внутри диапазона клиппирования: неклиппированное 1.15, клиппированное 1.15, минимум 1.15, обрезка не сработала, выгода продолжает расти вместе с отношением вероятности. При r_t = 1.5 значение выходит за верхнюю границу диапазона: неклиппированное 1.5 · 1 = 1.5, клиппированное clip(1.5, 0.8, 1.2) · 1 = 1.2 · 1 = 1.2, минимум 1.2. Выгода застряла на уровне 1.2, хотя вероятность действия по факту выросла в полтора раза, дальнейший рост r_t больше не поощряется. Если вероятность полезного действия упала до r_t = 0.5: неклиппированное значение 0.5 · 1 = 0.5, клиппированное clip(0.5, 0.8, 1.2) · 1 = 0.8 · 1 = 0.8, минимум 0.5. Выгода взяла меньшее неклиппированное значение, поэтому штраф за упавшую вероятность полезного действия никуда не делся, обрезка его не гасит.

Случай отрицательного преимущества A_t = -1 для плохого действия разбирается зеркально. При r_t = 1.5 плохое действие стало заметно более вероятным: неклиппированное 1.5 · (-1) = -1.5, клиппированное clip(1.5, 0.8, 1.2) · (-1) = 1.2 · (-1) = -1.2, минимум -1.5. Полный градиентный сигнал на снижение вероятности этого действия сохраняется, обрезка тут не помогает ухудшению политики. Если вероятность плохого действия уже снизилась до r_t = 0.5: неклиппированное 0.5 · (-1) = -0.5, клиппированное clip(0.5, 0.8, 1.2) · (-1) = 0.8 · (-1) = -0.8, минимум -0.8. Выгода застряла на клиппированном значении. Дальнейшее снижение вероятности плохого действия она больше не поощряет.

Общий вывод по всем случаям: обрезка гасит стимул только в ту сторону, где параметры уже получили заметное изменение за текущий шаг, полезное действие стало значительно вероятнее или плохое значительно менее вероятным. А сторону, где ещё есть что исправить, обрезка не трогает и оставляет градиенту полную силу.

python
def ppo_clip_objective(r, advantage, eps=0.2):
    unclipped = r * advantage
    clipped = max(1 - eps, min(r, 1 + eps)) * advantage
    return min(unclipped, clipped)


for r in [0.5, 1.0, 1.15, 1.5]:
    print(r, ppo_clip_objective(r, advantage=1.0))

# 0.5 0.5
# 1.0 1.0
# 1.15 1.15
# 1.5 1.2
Обрезка не единственная защита

Название «Proximal» выбрано не случайно: его цель удерживать новую стратегию вблизи той, которая собирала данные для обновления. Обрезка отношения вероятностей в PPO служит дешёвым приближением к честному ограничению на расстояние между стратегиями, которое реализует более ранний метод TRPO через расчёт вторых производных и стоит существенно дороже в вычислениях.

На практике PPO выполняет несколько проходов оптимизатора по одной и той же собранной партии траекторий, экономя на генерации новых данных. Клиппирование внутри функции потерь L^CLIP как раз и не даёт этим повторным проходам слишком далеко увести стратегию от исходной, которая эти данные собрала. Коэффициент обрезки ε обычно берут равным 0,2, и это же значение стоит по умолчанию в реализации GRPOConfig из библиотеки TRL, к которой глава ещё вернётся.

Состояние, действие и награда при генерации текста

Чтобы применить градиент по стратегии к языковым моделям, достаточно дословно перенести определения марковского процесса принятия решений из главы 36 на авторегрессивную генерацию текста. Состояние s_t на шаге t это промпт вместе со всеми уже сгенерированными токенами, то есть весь текущий контекст. Действие a_t это выбор одного токена из словаря модели, то есть того самого огромного дискретного пространства действий, о котором шла речь в начале главы. Стратегия π_θ(a_t|s_t) это и есть сама языковая модель: её выходное распределение вероятностей по следующему токену при заданном состоянии. На практике это распределение чаще называют вероятностями токенов, но по сути это та же стратегия, что и в разделе про REINFORCE.

Эпизод в этой постановке это генерация одного полного ответа: от первого сгенерированного токена до токена конца последовательности или до достижения предела длины. Траектория τ это конкретная последовательность токенов, выбранных моделью в этом эпизоде. При таком отображении не нужно изменять ни одну формулу из предыдущих разделов: оценка градиента по стратегии, базовые линии, формула PPO работают с текстом точно так же, как работали с простыми окружениями, например с пингвином на льду из главы 36. Это ровно то соответствие, на котором строится второй шаг RLHF из главы 10: после дообучения по инструкциям или с помощью LoRA мы применяем алгоритмы из семейства градиента по стратегии, чтобы подогнать распределение вероятностей модели под предпочтения людей, оценивая каждую сгенерированную последовательность одной наградой.

В авторегрессивной генерации текста понятия MDP из главы 36 переносятся дословно: состояние s_t это префикс, который уже сгенерирована до шага t, действие a_t, выбор следующего токена по распределению π_θ(·|s_t), а состояние s_{t+1} образуется добавлением этого токена к префиксу. Функция ценности V^π(s_t) оценивает ожидаемую кумулятивную награду, если от текущего префикса продолжать по стратегии π. Здесь нет готовой шахматной доски, но смысл тот же: каждое действие меняет состояние, и модель выбирает токен, исходя из того, какой доход это принесёт.

Основной сигнал приходит один раз, когда ответ полностью сгенерирован. Модель награды из главы 10 оценивает весь ответ целиком одним числом, поэтому награда здесь предельно разреженная. Это ровно тот случай, о котором предупреждал раздел про дисперсию: сигнал приходит в конце, а не на каждом шаге, и оценка REINFORCE разбросана. Теперь роль шахматной партии играет целый сгенерированный ответ, а не одна партия за 40 ходов.

Вдобавок к этой разреженной награде на каждом шаге вычитают маленький штраф, пропорциональный расхождению между текущей стратегией π_θ и опорной моделью π_ref. Это ограничение на отклонение от SFT-версии, о котором глава 10 говорила, не разбирая его формально. Зная теперь про базовую линию и преимущество, это можно назвать точнее: это часть награды на каждом шаге, встроенная прямо в формулу. Она не даёт стратегии уйти в зону, где модель награды выставляет случайно высокие оценки бессмысленному тексту, то есть не даёт случиться взлому награды.

При авторегрессивной генерации текста мы переносим постановку марковского процесса принятия решений из главы 36. Состояние s на шаге t это уже сгенерированная часть ответа, действие a это следующий выбранный токен, а награда r присваивается только после полного завершения генерации по результатам работы модели награды. Стратегия π в этой постановке это сама обучаемая языковая модель, которая по частично сгенерированному состоянию строит распределение вероятностей на следующие токены. Это ровно та структура, на которой строится второй шаг RLHF из главы 10, где мы вместо дообучения по максимальному правдоподобию максимизируем ожидаемую награду стратегии.

На диаграмме RLHF из главы 10 одновременно хранятся три модели: дообучаемая стратегия, модель награды и опорная модель. Если к этой постановке применить метод актор-критика из раздела про снижение дисперсии оценки градиента, к этим трём сетям добавляется четвёртая: критик, оценивающий значение состояния V(s) для каждого частично сгенерированного ответа. На практике критик это отдельная сеть, часто сопоставимая по размеру с самой обучаемой языковой модельой, что существенно повышает затраты на видеопамять при обучении PPO.

Следующий раздел разбирает метод GRPO, который убирает эту четвёртую сеть целиком, сохраняя низкую дисперсию оценки градиента.

GRPO и честное сравнение с DPO

GRPO расшифровывается как Group Relative Policy Optimization, метод предложили авторы во главе с Shao в 2024 году в статье DeepSeekMath. В конце предыдущего раздела мы упоминали, что классический критик в PPO это отдельная нейросеть, которая тратит ресурсы только на оценку базовой линии для снижения дисперсии градиента.

Механизм GRPO убирает эту отдельную сеть. Для одного и того же промпта сэмплируют группу из G ответов текущей стратегией, каждый ответ оценивает функция награды, например проверка корректности ответа. Преимущество i-го ответа вычисляют по формуле A_i = (r_i - mean(r)) / std(r), где r_i, награда i-го ответа, mean(r) и std(r), среднее и стандартное отклонение наград по группе. Роль базовой линии здесь выполняет эмпирическое среднее по свежим сэмплам на тот же промпт, без отдельной обученной сети. Это продолжение идеи базовой линии из раздела про дисперсию, только базовая линия оценивается по группе сэмплов, а не предсказывается внешней моделью.

По сравнению с PPO GRPO снижает расходы на обучение для больших языковых моделей, так как не требует отдельной сети критика. DPO из главы 10 дешевле GRPO на шаг, так как работает с парами ответов без явной награды, но менее устойчив к шуму в данных из-за отсутствия групповой нормировки преимуществ. GRPO не требует пар предпочтений, достаточно функции проверки ответа и сэмплов стратегии, что упрощает подготовку данных для RLHF на задачах с проверяемым результатом.

A_i = (R_i - mean(R_1, ..., R_G)) / std(R_1, ..., R_G)Важно: здесь R_i это награда i-го ответа на один промпт, оценка модели наград из главы 10. Это не r_t(θ) из раздела про PPO: разные обозначения с похожим написанием. Она считает преимущество ответа: из его награды вычитают среднее по группе, делят на стандартное отклонение наград. Ответ лучше типичного получает положительное A_i, хуже типичного отрицательное, абсолютный масштаб наград не важен.

GRPO полностью исключает критик из пайплайна обучения, то есть четвёртую сеть, о которой шла речь в конце предыдущего раздела. В памяти при обучении остаются только три компонента: обучаемая стратегия, модель награды или даже просто проверяемая функция без отдельной сети, и опорная модель, которая ограничивает отклонение стратегии от исходного поведения. Отказ от отдельной оценки ценности состояния это прямое следствие замены критика группой сэмплированных ответов.

За это приходится платить увеличением вычислительных затрат на генерацию за один шаг обучения. Вместо одного ответа на промпт нужно сэмплировать целую группу из G ответов для каждого обновления стратегии, что требует G проходов модели вместо одного.

GRPO особенно хорошо подходит для задач с дешёво проверяемой наградой: например, когда нужно проверить, верно ли решена математическая задача, или прошёл ли сгенерированный код тесты. В таких сценариях не нужна ни разметка предпочтений, как в DPO, ни отдельно обученная сеть модели награды, как в PPO. Достаточно реализовать быструю проверяющую функцию, которая возвращает числовую оценку для каждого ответа из группы. По сравнению с PPO, GRPO снижает потребление памяти, так как не требует хранения и обновления параметров критики, но увеличивает нагрузку на генерацию. По сравнению с DPO, метод не зависит от наличия пар предпочтительных и непредпочтительных ответов, что делает его более устойчивым, когда качественная разметка недоступна или её получение слишком дорого.

Вы уже знаете из предыдущих глав, что все три метода. PPO, GRPO и DPO из главы 10, в конечном счёте решают одну задачу: выравнивание языковой модели с предпочтениями пользователя, но принципиально по-разному устроены. DPO никогда не сэмплирует ответы из собственной обновляемой стратегии во время обучения. Он работает на заранее собранном наборе пар предпочтений, где для каждого промпта есть один предпочтительный и один нежелательный ответ, и использует одну фиксированную функцию потерь. По устройству обучения он ближе к обычному дообучению с учителем из главы 10, чем к онлайн-методам, и именно поэтому он стабильнее и дешевле в эксплуатации.

PPO и GRPO, наоборот, относятся к онлайн-методам. На каждом шаге обучения они генерируют свежие ответы текущей версией стратегии, получают по ним сигнал о качестве и сразу обновляют веса модели. GRPO при этом заменяет отдельную модель критика, требуемую в классическом PPO, на группу сэмплированных ответов на один и тот же промпт: среднее значение награды по группе используется как базовая линия для снижения дисперсии оценки градиента. Это даёт им возможность использовать любую вычислимую награду, а не только пары предпочтений из заранее собранного набора: например, проверяемую корректность ответа или соответствие формату. За такую гибкость они платят необходимостью поддерживать инфраструктуру для генерации ответов на каждом шаге обучения и более тонкой настройкой гиперпараметров, влияющих на стабильность сходимости.

Коротко: DPO дешевле и устойчивее, PPO и GRPO дороже по вычислениям, но гибче по типу сигнала, который можно превратить в награду для обучения.

from datasets import load_dataset
from trl import GRPOConfig, GRPOTrainer

def reward_len(completions, **kwargs):
    # награда выше, когда ответ ближе к 20 символам
    return [-abs(20 - len(c)) for c in completions]

    num_generations=4,
    logging_steps=10,
)
trainer = GRPOTrainer(
    model="Qwen/Qwen2.5-0.5B-Instruct",
    reward_funcs=reward_len,
    args=training_args,
    train_dataset=dataset,
)
trainer.train()

Коротко

  1. Когда количество действий слишком велико или они непрерывны, выбор действия через argmax по Q-значениям из Q-обучения перестаёт быть практичным, поэтому стратегию параметризуют напрямую весами θ и сэмплируют действия из получившейся распределённой модели.
  2. Теорема о градиенте по стратегии выводится приёмом логарифмической производной и даёт формулу REINFORCE: направление обновления θ равно сумме градиентов log π_θ(a|s) по всем шагам эпизода, каждый шаг взвешен одной и той же отдачей, из-за чего итоговая оценка получается сильно шумной.
  3. Вычитаемая из отдачи базовая линия не смещает математическое ожидание градиента, но резко снижает его дисперсию, а разность между отдачей конкретного действия и этой базовой линией называется преимуществом.
  4. Актор-критик обучает две сети одновременно: актор выбирает действия и обучается по градиенту по стратегии, а критик оценивает ценность состояния и поставляет актору низкодисперсионную оценку преимущества, решая эту задачу как обычную регрессию.
  5. PPO ограничивает шаг обновления, обрезая отношение новой и старой вероятностей действия внутри узкого диапазона вокруг единицы, поэтому выгода перестаёт расти за пределами этого диапазона, и один неудачный шаг не разрушает всю стратегию сразу.
  6. При генерации текста состояние состоит из промпта с уже сгенерированными токенами, действие это выбор следующего токена, а награда чаще всего разреженная и приходит от модели награды только в конце ответа. GRPO убирает критика, оценивая преимущество по группе ответов на один и тот же промпт, что дешевле PPO по памяти, но требует нескольких сэмплов на шаг и остаётся дороже DPO, зато допускает любую проверяемую награду, а не только пары предпочтений.

Проверьте себя

6 вопроса. Ответ показывается сразу с объяснением.

1. Вы обучаете робота-манипулятора управлять углом каждого сустава, угол это вещественное число из непрерывного диапазона. Почему подход Q-обучения из главы 36 здесь плохо применим напрямую?

Правильный ответ верен, потому что в Q-обучении из главы 36 выбор действия строится на argmax по Q(s,a) по конечному списку возможных действий. В задании же пространство углов непрерывное, перебрать все значения без отдельной оптимизации на каждом шаге невозможно. Остальные варианты неверны: Q-обучение успешно применяется к роботам, нейросети предсказывают вещественные числа, для роботов функция ценности существует.

2. Эпизод из пяти действий закончился с сильно отрицательной отдачей G. Что базовая формула REINFORCE сделает с вероятностями всех пяти действий этого эпизода на данном шаге обновления?

Правильный ответ верен, потому что в формуле ∇J = E[Σ_t ∇log π(a_t|s_t)·G] отрицательное значение G умножается на градиент логарифма вероятности каждого из пяти действий эпизода, что даёт отрицательный вклад и понижает их вероятности при обновлении. Остальные варианты неверны: отдача не привязана только к последнему действию, обновление происходит сразу после эпизода, а отрицательная отдача не делает опыт полезным для повышения вероятностей.

3. В некотором состоянии отдачи трёх сэмплированных действий равны 998, 1005 и 1010, а критик оценивает V(s) как 1000. Что даёт вычитание этой базовой линии перед тем, как использовать эти числа в градиенте?

Правильный вариант верен, потому что вычитание функции, зависящей только от состояния, не меняет матожидание оценки градиента и не даёт систематического сдвига в положительную сторону, как в первом неверном ответе. Оно не убирает необходимость сэмплирования нескольких действий и не превращает задачу обучения стратегии в Q-обучение. Вместо этого оно делает разницу между действиями заметнее и снижает дисперсию оценки: в примере числа 998, 1005, 1010 превращаются в наглядные -2, +5, +10.

4. В связке актор-критик критик неделю не обучался и стал предсказывать V(s) с большой ошибкой, хотя актор продолжает выбирать разумные действия. Что произойдёт с обучением актора?

Верный вариант. Критик вычисляет оценку преимущества A_t = r + γV(s') - V(s), и этот сигнал напрямую обновляет параметры актора. Если предсказание V(s) неверно, сама величина A_t искажается. Актор получает градиент в ложном масштабе или направлении, даже если его собственная политика разумна. Остальные варианты отвергаются: актор и критик связаны обратной связью, они не независимы. Актор не переключается на argmax по Q, это требует иного алгоритма. Критик не заменяется моделью награды, он остаётся отдельной сетью, предсказывающей ценность состояния.

5. При обновлении PPO с ε=0.2 действие с преимуществом A=-1 имеет отношение вероятностей r=0.5, то есть его вероятность уже больше чем вдвое снижена по сравнению с той стратегией, что собрала данные. Что покажет клиппированная выгода L^CLIP в этой точке?

Правильный ответ верен, потому что по формуле L^CLIP = min(r·A, clip(r, 1-ε, 1+ε)·A) при подстановке r=0.5, A=-1, ε=0.2 получаем min(-0.5, -0.8) = -0.8. Клиппирование блокирует дальнейшее снижение выгоды и удерживает её на этом значении, не поощряя ещё большее уменьшение вероятности действия. Первый вариант неверен, так как клиппирование предотвращает падение выгоды при дальнейшем отклонении r от 1. Второй неверен, потому что механизм только ограничивает диапазон r и не возвращает его к исходному значению. Третий неверен, так как шаг обновления стратегии всё равно выполняется, только градиент от этой части цели перестаёт расти.

6. Команда хочет дообучать модель по награде, которая проверяет, скомпилировался ли сгенерированный код, без разметки пар предпочтений людьми и по возможности без обучения отдельной сети-критика того же размера, что и модель. Какой метод из главы подходит лучше всего?

GRPO подходит, потому что он оценивает преимущество по группу ответов на один промпт, не требует критика и работает с любой проверяемой функцией награды, как компиляция кода. DPO исключён, потому что нуждается в парах предпочтений, которых в условии нет. PPO требует обучения критика того же размера, что и модель, что противоречит ограничению. Q-обучение из главы 36 не адаптировано для языковых моделей и не решает задачу градиентного обновления по стратегии.
