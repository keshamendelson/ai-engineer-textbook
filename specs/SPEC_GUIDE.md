# Как писать спеку главы

Спека это JSON, из которого `tools/write_chapter.py` собирает готовую главу.
Разделение труда жёсткое: **структура, схемы, таблицы, код, формулы, ключи к квизу
и ссылки на источники пишутся руками в спеке**, а прозу по вашим кратким заданиям
пишет модель. Модель врёт в фактах, поэтому всё, что нельзя проверить взглядом,
в спеку не попадает.

Образец для подражания: `specs/ch13.json`. Проверка: `python3 tools/check_spec.py specs/chNN.json`.

## Верхний уровень

```json
{
  "id": "ch20",
  "num": "20",
  "part": "Часть VI. Классические задачи NLP",
  "title": "Разметка последовательностей и поиск сущностей",
  "about": "о чём глава, одно предложение в 25-40 слов, попадёт в промпт каждого блока",
  "known": "что читатель уже знает из прошлых глав, перечислением с указанием глав",
  "meta": ["Нужны главы 8, 20", "Код: spaCy"],
  "sections": [ ... ],
  "recap": ["пункт итогов", "..."],
  "quiz": [ ... ],
  "scripts": "<script>…</script> для интерактивного демо, если оно есть"
}
```

Поле `meta` это правая часть плашки под заголовком. Время чтения туда **не пишем**,
его проставит `tools/estimate_time.py` по факту.

Поле `known` работает против повторных объяснений: термины оттуда модель считает
известными. Всё, чего там нет, глава обязана объяснить сама при первом появлении.

## Разделы и блоки

```json
{"id": "bio", "h2": "Схема BIO", "brief": "чем разметка по токенам отличается от разметки по сущностям",
 "blocks": [ ... ]}
```

`id` только латиница в нижнем регистре, это якорь для поиска и меню.

### prose

```json
{"type": "prose", "words": 220, "brief": "Объясни то-то. Приведи такой-то пример. Скажи, что …"}
```

Задание пишется приказами: «объясни», «покажи», «перечисли три», «скажи, что».
Все числа, названия моделей и библиотек указывайте прямо в задании, иначе модель
их выдумает. Один блок это 150-260 слов, больше не просите.

### figure

```json
{"type": "figure", "caption": "что на схеме и что читатель должен из неё вынести",
 "svg": "<svg viewBox=\"0 0 700 300\" role=\"img\" aria-label=\"…\">…</svg>"}
```

SVG пишется руками. Правила:

- только `viewBox`, без `width` и `height`, схема тянется по ширине текста;
- обязательны `role="img"` и осмысленный `aria-label`;
- **никаких зашитых цветов и размеров шрифта**, только классы ниже, иначе схема
  сломается в тёмной теме;
- `id` внутри `<svg>` (маркеры стрелок, градиенты) должны быть уникальны в пределах
  главы: префиксуйте их, например `ner-ar`, `ctc-ar`.

Классы оформления, других нет:

| класс | что это |
|---|---|
| `s-box` | обычная рамка |
| `s-box-a` | рамка с акцентом, синяя |
| `s-box-w` | предупреждение, оранжевая |
| `s-box-g` | хорошее состояние, зелёная |
| `s-box-v` | второй акцент, фиолетовая |
| `s-line`, `s-line-a`, `s-line-d` | линия обычная, акцентная, пунктир |
| `s-t`, `s-t-b`, `s-t-s`, `s-t-xs`, `s-t-a` | текст обычный, жирный, мелкий, очень мелкий, акцентный |
| `s-fill-a`, `s-fill-2`, `s-fill-3` | заливка для стрелок и точек |
| `s-mono` | моноширинный текст в схеме |
| `s-bg` | фон под текстом |

Стрелка делается так:

```xml
<defs><marker id="ner-ar" markerWidth="8" markerHeight="8" refX="6.5" refY="4" orient="auto">
<path d="M0,0 L8,4 L0,8 z" class="s-fill-a"/></marker></defs>
<path d="M138,71 L156,71" class="s-line-a" marker-end="url(#ner-ar)"/>
```

### callout

```json
{"type": "callout", "kind": "warn", "title": "Где это ломается", "words": 110,
 "brief": "…", "see": "необязательно: буквальный текст кода, о котором врезка"}
```

Виды: `info` синяя дополняет, `analogy` фиолетовая даёт аналогию, `warn` оранжевая
предупреждает, `practice` зелёная задание, `math` бирюзовая выкладка, `danger` красная.

Задание в конце главы это `practice` с заголовком вида
`"Сделайте руками · 90 минут"`. Время из заголовка попадает в подсчёт трудоёмкости,
поэтому пишите его явно.

### deeper

Раскрывающийся вывод формулы или разбор пограничного случая.

```json
{"type": "deeper", "title": "Вывод: почему делят на корень из d", "words": 280,
 "brief": "что выводим и зачем",
 "steps": ["шаг вывода с обозначениями", "следующий шаг", "…"]}
```

Шаги пишете вы, полностью и в правильных обозначениях. Модель только разворачивает
их в текст. Если вы не можете написать шаг сами, блок не нужен.

### formula, table, code, html

```json
{"type": "formula", "fx": "P(w | h) = count(h w) / count(h)", "brief": "что пояснить"}
{"type": "table", "html": "<table><thead>…</thead><tbody>…</tbody></table>"}
{"type": "code", "label": "python", "code": "import torch\n…"}
{"type": "html", "html": "<div class=\"demo\">…</div>"}
```

Код пишется руками и должен работать. Никаких выдуманных функций и параметров.

### sources

Ссылки на первоисточники, через модель не идут.

```json
{"type": "sources", "title": "Где про это написано подробнее",
 "items": [
   {"ref": "Jurafsky, Martin. Speech and Language Processing, глава 18", "url": "https://web.stanford.edu/~jurafsky/slp3/", "note": "HMM, Витерби и CRF с полными выкладками"},
   {"ref": "Lafferty, McCallum, Pereira. Conditional Random Fields, 2001", "url": "https://repository.upenn.edu/cis_papers/159/", "note": "исходная работа про CRF"}
 ]}
```

Ссылку, в существовании которой вы не уверены, не ставьте. Проверка ссылок:
`python3 tools/check_links.py specs/chNN.json`.

## Квиз и итоги

```json
"quiz": [
  {"q": "текст вопроса", "opts": ["вариант", "вариант", "вариант", "вариант"],
   "right": 2, "hint": "на чём основан правильный ответ, для объяснения"}
]
```

Шесть вопросов, четыре варианта, `right` это индекс с нуля. Вопросы про понимание,
а не про запоминание слов: ситуация и выбор действия работают лучше определений.

`recap` это 6 пунктов, каждый одно-два предложения, по ним модель пишет итоги.

## Правила текста, которые нарушать нельзя

1. Никакого длинного и среднего тире. Ни в спеке, ни в заданиях модели.
2. Никаких антитез «не X, а Y», «не просто X», «больше чем X».
3. Никакого канцелярита: является, осуществляет, представляет собой, в рамках, данный.
4. Никакой раздутой значимости: играет ключевую роль, знаменует, открывает горизонты.
5. Заголовки без двоеточия по шаблону «Термин: пояснение».
6. Обращение на «вы», учебный регистр, без восклицаний.

Читатель это вчерашний школьник, который умеет писать на Python и больше ничего
не знает. Каждый новый термин вводится один раз и сразу расшифровывается,
на английский оригинал ссылаемся в скобках при первом упоминании.


## Осторожно с выдержкой из корпуса

Заголовки разделов в корпусе отстают от текста: сборщик брал ближайший заголовок,
встреченный внутри куска, а не в его начале. `tools/source_extract.py` это
компенсирует, добавляя к каждому найденному куску предыдущий, но проверять всё
равно надо: **прочитайте первые абзацы выдержки и убедитесь, что там та тема,
которая нужна**. Если в выдержке про графовые сети вместо автокодировщиков,
запустите извлечение с другим номером главы или с `--grep` по ключевому термину.

Если нужного материала в источнике нет, пишите раздел по общеизвестным фактам
и честно не ставьте на него ссылку в блоке sources. Выдуманная ссылка хуже
отсутствующей.

## Порядок работы

```bash
python3 tools/source_extract.py --book slp3 --chapter 18 --out /tmp/slp18.txt
# пишете спеку, опираясь на выдержку
python3 tools/check_spec.py specs/ch20.json
python3 tools/write_chapter.py specs/ch20.json --workers 12
python3 tools/lint.py site/ch20.html
python3 tools/estimate_time.py --write
```
